# Uberhar 0.1.3 — prepared TEV operands

<!-- AstraEH: Reduce repeated fragment decoding while preserving the established generic path. -->

## Changes

Prepare draw-constant operand information on the CPU alongside the existing TEV
stage plan:

- Resolve stage-zero Previous references from the original third operand once.
- Encode color/alpha component selection and inversion directly.
- Pass literal scale multipliers, including the two original scale-one encodings.

The generic fragment shader consumes these prepared values instead of repeating
register interpretation for each fragment. The transport stays 128 bytes and
uses ABI 7 to distinguish the new semantics. Family keys, operation arithmetic,
rounding, lazy texture reuse, stage order and delayed combiner-buffer writes
remain unchanged. Missing compilation still waits or uses validated recovery;
no draw is skipped.

This exchanges a small amount of per-draw CPU preparation for less per-fragment
decoding. Its net benefit depends on the device and workload; CPU-heavy scenes
are an explicit regression check. This is not pipeline prewarming.

## Validation

Local validation passed:

- 208,896 exact RGBA8 comparisons and texture-use checks across 816 TEV programs.
  Eighty additional cases cover every legal color/alpha modifier pair, with
  stage-zero source redirection, operation arities and scale encodings.
- Texture-fetch expectations now read original effective guest registers, separately
  from prepared state, so a transport mistake cannot redefine the expected result.
- 1,081,344 exact color comparisons and the same number of depth/discard checks
  across 1,056 full fragment states.
- 1,066 Vulkan modules validated both before and after optimization, including
  loop control and 128-byte ABI checks.
- Production generator corpus under address/undefined-behavior sanitizers;
  host correctness suite and Vulkan pipeline-cache integration syntax check.

Android compilation, package/signature validation and publication remain gated
by Actions. Host checks do not demonstrate a Thor speedup or physical input latency.
