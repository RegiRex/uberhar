# Uberhar 0.1.17 — optional Android crash evidence, available as files

<!-- AstraEH: Owner explicitly accepted a supplementary Android crash saver, outside the app UI. -->

## What changes

- Save available Android exit evidence into **`log/crashes/` in the existing Uberhar
  data folder**, recovered once on the next app launch. A readable dated summary
  records the source build, actual OS exit time, reason/status or signal, description
  and available sampled memory information. Retain an available native tombstone or
  other OS trace as a separate file beside it.
- Remove the in-app Crash reports button/browser. The ordinary current/previous/older
  export remains. Previously retained interruption/legacy reports move to the same
  file-only folder after verification; failed copies keep their private source.
- Android capture is optional and defaults on. Set `android_crash_reports=false` in
  `config/config.ini`'s `[Debugging]` section while Uberhar is closed, then restart to
  disable it. Base text logging/retention and moving already-saved evidence still work.
- One background startup check examines at most eight OS records and saves at most
  two new abnormal exits. Reports are attributed only to tagged Uberhar builds/processes.
  No constant monitor, per-launch bundle, second live log writer, extra permission,
  network service, telemetry SDK or native crash-handler replacement.
- Cap individual traces at 8 MiB and OS descriptions at 4,096 characters; a tiny
  32-entry ledger prevents repeated saves. Missing or oversized traces still produce
  the small exit summary. Ordinary exits create no reports.

0.1.16 passed all build/release gates. No new user/device results or renderer changes
are claimed in 0.1.17. New comments continue to use AstraEH. The default full review
remains after 0.1.17 evidence, within the existing 0.1.16–0.1.18 window.

## Access and interpretation

Use a file manager to open the Uberhar data folder, then `log/crashes/`. Look for
`uberhar_android_<exit UTC>_<PID>_<token>.txt`. For a native crash, share that summary
and the matching `.tombstone.pb` if present, plus the relevant ordinary text log.
Other OS trace data uses `.trace.bin`. These are files, not compressed bundles.
Existing interrupted logs are named separately and are not proof of a native crash.
The normal log records a short location pointer after saving, or a pending-save line
if the folder/provider was unavailable. No in-app crash listing or capture popup.

Android collects the failure; Uberhar cannot reliably finish work after its process
has died. Recovery therefore happens on restart. Exit history needs API 30+, and native
tombstones need API 31+; unsupported/missing services are skipped without affecting
play or normal logging. OS traces may be absent or expired. The initial tagging window
and crashes from untagged older builds are not guessed or mislabeled.

Native tombstones are preserved as original protobuf bytes for offline decoding and
symbolication against the saved build ID/symbols. A text exit summary alone may not
reveal the underlying bug. Low-memory/signal exits are explicitly labeled and must
not automatically be interpreted as renderer crashes. RSS/PSS are sampled, not peak.
This is stronger potential evidence, not a guarantee of capture or root-cause detection.

A verified file copy retires the private staging bytes to avoid permanent duplication.
Conflicting files are never overwritten. Saved incident files remain until manually
deleted in the file manager, so repeated actual failures can consume storage. No new
normal-launch archives are created. One-time migration/recovery can do storage IO;
normal emulation does not wait for the optional background collector.

## Validation and short device check

33 host JVM tests pass across base retention/export names, tagged identity, exact binary
preservation, missing/oversized traces, interrupted commits, deduplication, bounded
metadata and provider transfer faults/conflicts. Native/rendering behavior is unchanged;
existing Android compilation, shader correctness, packaging/signing and publication
gates remain mandatory. Android API/SAF/file-manager and physical-device validation
are still pending, including GammaOS.

After publication, update without clearing data. Ordinary log export should show only
current/previous/older and no Crash reports action. If a genuine crash happens after
running this version, reopen Uberhar and check `log/crashes/`. There is no request for
a deliberate crash, long Dark Moon failure replay or full benchmark suite.
