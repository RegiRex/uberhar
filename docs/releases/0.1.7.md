# Uberhar 0.1.7 — fused vertex input and recovery visibility

<!-- AstraEH: Shared hot-path optimization selected by the full 0.1.6 architecture review. -->

## What changes

Prepare bounded attribute spans, register destinations and scalar decoders once
per admitted no-geometry Native batch. Read live data directly into VS input
registers instead of repeatedly mapping each attribute and copying a temporary
AttributeBuffer. Retain exact f24 conversions, default/alias semantics, FIFO,
shader execution, output conversion, assembly and draw order. Memory references
live only for the batch. Unknown layouts, wraparound and short spans retain the
legacy loader; geometry/debug paths are unchanged. All experimental modes share
this CPU transport, so the improvement is not exclusive to the Native UI label.

Check existing fragment support before preparing unused dynamic TEV state on
specialized-only draws. Supported draws still construct complete snapshots.
Add bounded aggregate input-admission and exclusive specialized-recovery reasons.
No support guard, shader arithmetic, ABI7, graphics pipeline key, cache format,
driver workaround, application identity or signing policy changes.

## Why this change

The cumulative twelve-session 0.1.6 evidence reports no eligible compute rectangles
in any mode, and MH4U uses specialized fragment recovery for 77.176% of its draws.
Its final 400%-commanded intro averages 87.785% over 706.835 observed seconds.
Generic-only shader tuning and menu peak comparisons miss the central problem.
The full review is in [UBERHAR_ARCHITECTURE_0.1.6.md](../UBERHAR_ARCHITECTURE_0.1.6.md).

## Validation status and limits

The fused input helper passes 36864 bitwise comparisons against independent scalar
conversion plus production ShaderUnit::LoadInput, including mixed formats,
unaligned addresses, alias registers, live defaults/data, 8/16-bit and large
non-indexed offsets, range/overflow/retention rejection and re-preparation. The
same input tests pass address/undefined-behavior sanitizers. The existing host
family, pipeline, vertex output/FIFO, interpreter, phase/frame/cache accounting,
preparation and queued push-state probes also pass locally. PICA integration
syntax passes. Directed recovery-reason tests compare with the prior admission
predicate; no formerly rejected state is promoted.

Shader corpus generation is not shader pixel execution. Full Vulkan integration,
shader/pixel/Vulkan gates, Android compilation/unit tests, packaging/signing and
prerelease publication remain the existing Actions gates. Local Vulkan syntax
was blocked by an unavailable robin-map dependency, not counted as a pass.
Thor performance and visual acceptance remain pending. No FPS gain is claimed
from host correctness tests; per-batch setup overhead and conservative admission
may reduce or eliminate gains on some workloads.

## What to test

Keep Native as the main path. Retain one familiar FEA 2x cold normal-speed test,
then a warm FEA 2x battle at a stable 400% cap. At 4x distinguish fixed400 capacity
from fixed200 usability. Use Sonic's actual race and MH4U's same intro at 2x for
sustained work; do not repeat character creation. Pause/resume and title changes
should not produce stale attributes or effects. Report scene context and visible
regressions; automatic settings/cache/path counters cover the technical metadata.

No further all-mode FEA matrix is required while every compute candidate is
rejected. Cold waits and high-resolution FEA ghosting are still open, not fixed
by this release. 0.1.7 is successor one after the full review of 0.1.6.
