# Uberhar 0.1.58 alpha — CPU work reduction and comparable diagnostics

<!-- CodexAstraLocal: Describe the reconciled implementation and explicit qualification boundary for the gated prerelease. -->

This alpha adds independently testable CPU conversion, vertex reuse and transport
optimizations, repairs adaptive qualification and contained-pass reuse, and extends
specialized shader pruning. The full specialized pipeline bank can be compared at
8 or 16 entries while retaining the existing compiler and lifetime budgets.

New default-OFF controls in alpha Testing:

- **Fast CPU vertex conversion**, including bounded deferred-packet scratch.
- **Reuse independent vertex results** within certified immutable chunks.
- **Indexed CPU output** for exact repeated packed vertices.
- **Worker CPU vertex upload** on the existing recorder.
- **Reject proven invisible CPU triangles** with conservative exact clip checks.
- **Full pipeline capacity: 8 / 16** (OFF=8, ON=16; partial bank remains 8).
- **Prune unused specialized shader work** in the actual SPIR-V path.
- **Mono guest 1% path**, separate from the normal saved 3D slider.

The mono experiment preserves real stereo and nonzero saved depth. It does not
remove all second-eye work. Early-eye eligibility checks cost less, but Dark Moon's
existing compatibility veto remains; shared offscreen consumers cannot safely be
discarded based only on screen location.

V38 static-state forcing is removed and archived by feature. Optimize generic
shaders, Turnip pass-end submission, unchanged-state reuse and typed primitive
append remain available. Global settings never override explicit title settings.
No advisory tuning action applies or restores settings automatically.

Performance diagnostics retain the existing five-second windows and add real
one-second sections, with six shortest/longest paired intervals per section and
session. Compact files use the existing logger and are included in log exports;
delivery loss and partial sections are explicit. Advisory reports compare to the
matched baseline first and a selected optimum second, respecting resolution and
driver context.

See the [decision ledger](../UBERHAR_DECISIONS_0.1.58.md),
[telemetry contract](../UBERHAR_FRAME_TELEMETRY.md), and
[advisory tuning workflow](../UBERHAR_PERFORMANCE_TUNING.md).

Host equivalence tests and Android compilation do not establish device performance.
The existing shader, Android, package, signing and publication gates remain required.
Thor testing follows publication in the owner's next session; no speed gain or
full-game visual qualification is claimed by these release notes.
