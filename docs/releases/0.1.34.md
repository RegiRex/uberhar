# Uberhar 0.1.34 — exact prepared vertex-input recipes

<!-- CodexAstraLocal: Explain the bounded input-loader optimization without claiming a measured game speedup or confusing generic CPU input handling with guest graphics fallback. -->

Four exact, complete vertex-input layouts can execute their original typed
conversions through one prepared recipe. This removes repeated per-attribute
reader dispatch for matching layouts. Each preparation still validates mappings
and ranges; live addresses, strides, register destinations, conversion order and
aliased writes retain their original meaning. Unmatched layouts and default
attributes use the existing generic prepared input loader.

The recipe and its identifier reset before every preparation or retry. Empty
draws avoid recipe selection. Shader execution, indexed FIFO behavior, state
carry, output conversion and primitive assembly remain unchanged. The optimization
applies to the shared CPU vertex path, including Native and the CPU portion of
Combo. Calculated retains .33's strict no-graphics-fallback policy; this change
does not implement its missing general 3D rasterization.

<!-- CodexAstraLocal: Describe the real-device benchmark preparation failure and the narrowly targeted compiler-path correction. -->

The isolated scratch benchmark now uses the Vulkan compiler's built-in macro
instead of redefining it. The .33 Thor request failed shader preparation before
recording any work; no timings or ratios came from that attempt. A new regression
executes the actual production compiler and benchmark preparation call against
the pinned parser. Twelve modules across four clip/logic profiles validate, and
the original conflicting preamble reproduces the failure. This exercises the
benchmark's explicit optimizer-disabled path, not optional optimized compilation.
The existing pixel/output and lifecycle gates remain required.

<!-- CodexAstraLocal: Define the actual-use denominator and bounded diagnostic cost so recognition is not reported as executed work or attributed time. -->

The existing vertex-input report advances to schema 2 with five invocation
counts: generic prepared input and the four recipes. Their sum equals
`fused_vertices` within the same PICA lifetime. Counts update once after the
existing FIFO runner using actual invocations, excluding reused indices and
escaped input loads. They do not measure time or identify visible actors.
The five counters occupy 40 bytes; reporting keeps the existing cadence.

<!-- CodexAstraLocal: Keep synthetic correctness, static compiler results and older recipe-only timing separate from final candidate performance. -->

The durable regression compares complete same-source generic and recipe paths,
using the actual legacy loader as an additional input oracle. It covers
interpreter/JIT execution, mappings/defaults/aliases, bounds/retries, state carry,
FIFO hits, output lanes and primitive tails, with deliberately broken controls.
The merged input-recipe and compiler-fix candidate passes native compilation,
CTest with five firmware-dependent skips, and the full host probe (583.330 seconds). The focused recipe gate covers 2,817 draws and
1,079,466 assertions, plus accounting checks and deliberately broken controls.
The final benchmark pixel gate passes 16 original-input pairs, four deliberate
pixel defects and four Vulkan modules. Publication gates and device observations
remain pending at this source checkpoint.

Private recipe-only host experiments improved selected synthetic populations and
slightly regressed some generic populations. They exclude the later accounting
instructions and do not predict Thor speed. ARM64/API 33 object compilation
passes; final linked size, target cycles and useful title coverage need separate
evidence. Neither this candidate nor the isolated scratch benchmark establishes
sustained 99% normal speed or 4x qualification.
