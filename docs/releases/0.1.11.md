# Uberhar 0.1.11 — filesystem-only older log and crash-evidence retention

<!-- AstraPro: Owner-requested reliability update; no renderer correction is claimed. -->

## Changes

The selected user directory's `log` folder retains:

- `azahar_log.txt`: current process log.
- `azahar_log.old.txt`: previous nonempty process log.
- `azahar_log.older.txt`: one further generation, filesystem-only.

Before a fresh logger opens, rotate old to older and current to old. Keep the
existing filename and export choices: only current and old are exposed inside
the app. Do not add a third UI choice or change saved-log export naming. Rotation
happens on logger initialization, not on every game launch, export or frame.
Existing same-process initialization guard remains unchanged.

Missing/empty current logs do not evict history. Stop rotation on a reported
filesystem failure, and open current in append mode rather than truncate it.
Append is also safe after a successful rename because current no longer exists.
If rotation fails, sessions can share the current file; preserving evidence is
more important than perfectly separated sessions. The existing per-file 100 MiB
write limit counts any retained contents. Oldest-history eviction is intentional;
this is bounded history, not an indefinite crash archive or a multi-file atomic
transaction. No evidence already overwritten by an older build can be recovered.

Flush the first consumed entry and then approximately once per second of log
entry timestamps while records are processed, retaining error/export/shutdown
flushes. This avoids a clock syscall or flush for every normal log entry. It
reduces stdio buffering but does not guarantee preservation of messages still in
the async queue, the final crash instruction/backtrace, a hung logger or power
loss. There is no new signal handler, per-frame sync or forced device setting.

File operations continue through the existing FileUtil implementation including
Android raw-filesystem/SAF dispatch. Real Android document-provider behavior is
still a device check. New logical sections use AstraPro; existing credit stays.

## Dark Moon report and test decision

The owner reports graphical anomalies and eventual crash in 0.1.10 Combo, menus
roughly half Native's pace, mostly good FEA, and loss of the playtime log after
restart. Representative frames from the supplied video show broken/detached
geometry; the video is not a native crash trace. The surviving logs are older
builds and cannot establish the cause or precise 0.1.10 counters.

No retest of the unprotected 0.1.10 build is required before this logging update.
Renderer, shader profile, cache, driver, accuracy, saved configuration and game
behavior are unchanged in 0.1.11. This release is NOT a graphics/crash fix and
NOT a performance release. Use Native for ordinary gameplay. Do not deliberately
reach the Combo crash merely to test retention.

After publication, verify the backup with a short Native session and two full
app restarts; the first session's header should appear in .older.txt. Opening a
game again inside the same app process does not rotate. If a brief diagnostic
Combo reproduction is undertaken later, stop at the first clear anomaly, exit
normally and export the current log immediately. Avoid another long cutscene,
4x test or game-suite replay. Manually copy any crash log out of the log folder
before further restarts; a third subsequent rotation evicts it.

package/signing and publication gates remain unchanged and required. Commit,
