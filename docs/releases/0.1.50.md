# Uberhar 0.1.50 — scheduling repair, less repeated shader work, independent renderer fixes

<!-- CodexAstraLocal: Describe real execution changes and retain the distinction between release validation and Thor gameplay acceptance. -->
This candidate addresses the Native/Combo regressions found in the 0.1.39–0.1.49
assessment and integrates the pending Calculated and CPU Software work. It does
not claim a measured frame-rate gain before hardware testing. Complete draws,
guest ordering, saves and independent renderer failure handling remain required.

<!-- CodexAstraLocal: Small work needs sufficient useful parallelism; bounded histories must survive recurrence before their decisions can be useful. -->
CPU draw scheduling restores conservative standalone admission while preserving
useful grouping of already-pending small packets. Expanded small seeds are a
separate, default-off comparison. Exact accepted effects proofs reach their
consumer without a redundant shared lease. Adaptive sampling now survives history
eviction, protects a bounded set of useful learning windows, and becomes dormant
with sparse discovery when no recurring workload qualifies. Existing capacity,
complete-work, join-cost and output-order guards still govern decisions.

<!-- CodexAstraLocal: Enable qualified runtime arithmetic rather than counting theoretical opportunities as implemented savings. -->
Generic/static fragment paths now consume exact CPU-prepared endpoint results
for qualified constant texture-combiner expressions. Mutable colors and buffer
inputs participate in preparation identity without multiplying shader modules.
Directional preprocessing accepts only certified positive-Z unit vectors; other
directions retain their original arithmetic. Unused distance work can be omitted.
These are narrow exact substitutions, not a replacement for per-pixel lighting.
Ordinary texture reads share one invocation-local memo where reuse exists; single
consumers use direct reads. A bounded share of existing optional specialization
capacity is reserved for lit states without increasing its total capacity.

<!-- CodexAstraLocal: Preserve visibility and exact memory ownership while reducing observer and admission overhead. -->
Feedback command-epoch bookkeeping starts only after a reusable snapshot exists.
Resource reports move out of transfer hot paths. CPU-copy admission records the
complete rejected path but retains the current-RAM, nonaliasing and writer guards;
it does not introduce GPU readbacks. Attachment-ending reasons and submission
readiness are distinguished from actual fence waits. Required barriers remain.

<!-- CodexAstraLocal TEST-ONLY LOG: Remove qualification counters/controls after measured placement and arithmetic decisions; retain production errors. -->
Thirteen independent comparison/diagnostic controls are exposed under graphics
settings. GPU timestamps are **off by default**, separately from ordinary feature
counts. Optional execution-census atomics also default off. Game restart applies
renderer controls; execution-census changes require a complete app restart.
Periodic and final records identify effective controls, selected consumers,
refusals and sampled costs. CPU submission duration is not GPU execution time;
logical transfer bytes are not measured memory bandwidth. No saved milliseconds
are inferred from hit counts.

<!-- CodexAstraLocal: Software acceleration retains exact input checks and owned output order; do not advertise an unresolved invalid-input failure as fixed. -->
CPU Software adds exact prepared-combiner reuse, checked scanline coverage spans,
work-sized row dispatch and narrowly certified constant-fill groups. Groups own
their inputs and drain before dependency boundaries and failures. Read-time vertex
provenance preserves the actual bytes consumed when an input fails. The previously
observed Dark Moon live-NaN issue has no established numerical correction; the
guard remains active. Software is still experimental and its earlier very low
speed is not claimed resolved.

<!-- CodexAstraLocal: Calculated stays independent; driver retry is bounded and arithmetic qualification does not become an output tolerance. -->
Calculated integrates invocation-owned shader state, proven-inside emission,
bounded flat clipping storage and active-pixel dispatch. An original guest shader
rejected with Vulkan ERROR_UNKNOWN may receive one bounded structural SPIR-V retry;
both modules and the actual driver result remain attributable. It never silently
falls back to Native. The primary-color specialization remains unavailable because
an interpolation midpoint discrepancy is unresolved. Host checks do not establish
that the Thor driver will accept the retry or that either experimental mode will
complete the owner's games.

<!-- CodexAstraLocal: Keep publication gates and owner qualification as distinct acceptance steps. -->
The existing shader, Android, signing and publication gates remain required.
Focused validation covers changed scheduling/order, exact shader output and
mutable inputs, resource lifetime, diagnostics and Software work ownership.
Owner testing should first compare matched Native/Combo conditions, then make a
single consolidated launch/failure capture for each experimental mode. The target
remains correct cold rendering at 99%+ normal speed, qualifying 2x before 4x.

<!-- CodexAstraLocal: Preserve the first gate failure and distinguish repaired fixture dependencies from renderer changes. -->
The first shader gate exposed an ordinary-worker fixture that relied on a header
included only by its static-TEV variant. The companion lighting fixture also
needed a real consumed-lighting state and its prepared transport instead of
synthetic bytes. Both fixtures retain their ownership, output and failure checks;
these repairs do not change emulator execution.

<!-- CodexAstraLocal: Keep the subsequent constructor-contract repair attributable without weakening the invalidation oracle. -->
A subsequent gate reached the proof-cache fixture, whose two constructors still
omitted the new frozen worker policies. Both now pass those policies explicitly;
the baseline and all seven cache-invalidation defect controls pass unchanged.
The same review updated the input-recipe fixture for shared read-trace types and
the new generic-versus-recipe accounting partition. Its numerical comparisons
and existing defect checks pass, with two additional traced-accounting controls.
