# Uberhar 0.0.11 — CPU vertex cost and generic shader reuse

<!-- AstraEH: Response to the 0.0.10 battle slowdown and warm shader rebuilding. -->

The supplied eight-session 0.0.10 log showed all three profiles using native
rendering for every draw; compute coverage was zero. The CPU vertex stage consumed
about 64 seconds in each approximately 99-second warm Compute/Automatic session.
Warm Native also spent 5.22 seconds recreating generic shader modules despite a
working driver cache. See [the full analysis](https://github.com/RegiRex/uberhar/blob/uberhar/hybrid-shaders/docs/UBERHAR_LOG_ANALYSIS_0.0.10.md).

## Changes

- **Cached CPU shader JIT in all three profiles.** Restore the existing ARM64 CPU
  translation engine to address sustained battle slowdown. First-use CPU compilation
  is measured separately. GPU vertex interpretation remains unfinished.
- **Faster indexed vertex reuse.** Replace the linear 64-entry search with a fixed
  index while preserving the exact FIFO hit/eviction sequence and vertex order.
- **Allocation-free interpreter stacks.** Preserve the reference fallback's control
  flow and overflow behavior without three allocations per vertex invocation.
- **Persistent generic SPIR-V modules.** Reuse compatible generated modules on later
  launches. Damaged or incompatible entries rebuild normally. Files are written on
  the existing compiler worker and removed by the existing Vulkan-cache clear action.
- **Skip optional SPIR-V optimization in the profiles.** Reduce first-use frontend
  work; both optimizer modes remain covered by Vulkan validation gates.
- **More useful diagnostics.** Bounded CPU-stage windows, actual shader invocation
  and reuse counts, first-eight CPU JIT builds plus totals, generic-module cache
  counts, detailed compute blockers, and startup/live pipeline counts.

The controls remain mutually exclusive, preserve custom settings, and keep
resolution/integer scaling editable. New code sections carry **AstraEH** comments;
diagnostic calls carry **AstraEH Log Line** markers. No Android permissions,
application identity, signing configuration or driver workarounds change.

## Test

Use **Native at 2x**, clear the Vulkan cache once, play the same section including
a battle, exit normally, then repeat without clearing. Note battle FPS/speed and
export the log. Start with this pair; Compute/Automatic use the same improved CPU
route, and their still-limited rectangle subset had no coverage in Awakening.
An all-off Custom TEV+bridge pair is optional. Keep fast forward for a separate test.

The release still has first-use generic pipeline compilation and does not promise
zero hitches or full-speed battles. Host correctness tests are not Thor performance
measurements. Publish only after the ARM64, shader, package and signing gates pass.

## Local validation

The complete host probe passed, including 6,160 shader-family checks, 36 pipeline-key
checks, 264 bridge assembly comparisons, profile/compute admission and concurrent
wait accounting. New gates passed one million comparisons against the original
vertex cache, 200,000 stack operations, 30,000 production-interpreter invocations
with zero heap allocations in the test configuration, and module-cache corruption,
truncation and compatibility checks. All 163 Android setting keys and eight manifest
checks passed. Modified Vulkan, PICA and CPU JIT translation units passed host syntax
checks. ARM64 compilation, numerical GPU comparisons and APK validation remain
Actions gates; this is not a device performance result.
