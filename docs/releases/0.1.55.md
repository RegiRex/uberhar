# Uberhar 0.1.55

<!-- CodexAstraLocal: Keep the .53/.54 rendering base while repairing optional-work lifetime and adding requested testing/driver controls. Hardware performance remains unqualified at submission. -->
This candidate lets specialization continue adapting during longer sessions and
retains compatible optional shader work across launches. It also adds the requested
home Testing panel, per-game Testing preferences and driver exceptions. The
original complete generic rendering path remains available while optional work
is pending or fails. There is no new draw-skipping path.

- **Renewable specialization:** fixed resident limits remain, but compilation
  credits replenish instead of expiring for the rest of the game. Replacement
  respects compiler release, queued commands and completed GPU use. Exact-key
  failure history prevents repeated attempts at known failures; classified
  temporary failures receive limited, delayed retries.
- **Useful warm caches:** successful optional full/static shader artifacts and
  useful-demand records can survive a compatible relaunch. Identity and integrity
  checks reject incompatible/corrupt records. Driver blobs use compatibility
  directories so switching drivers need not overwrite another driver's cache.
  Normal shader-cache deletion still produces a cold test.
- **CPU overhead:** adaptive-only timing waits for a stable repeated workload
  shape. Rapidly changing batches avoid unproductive measurements without
  changing their worker allocation, ordering or explicitly requested diagnostics.
- **GPU evidence:** sparse nonblocking timestamps distinguish framebuffer and
  utility render passes. Queue-age samples and separate worker/submission/GPU
  waits help separate execution costs from scheduling gaps. These measurements
  do not report hardware memory bandwidth, individual GPU cores or shader-only
  execution time; presentation cost remains unmeasured by these queries.
- **Turnip pass-end submission:** a default-OFF experiment applies the existing
  natural pass-end submission policy to Turnip. It adds no forced GPU completion
  wait. Keep it separate from the specialization and driver comparisons.
- **Optimize generic shaders:** a default-OFF experiment enables optimization
  specifically for generic shader modules. It may improve execution at the cost
  of first-use compilation time. Existing required shader correctness gates remain.
- **Testing shortcuts:** home **Options**, directly below the flower, now has
  the same Testing controls as Settings. Preset and resolution can be remembered
  per game independently from normal saved preferences. Turning Testing off
  restores ordinary settings. Resolution can change during play; rendering-model
  and driver changes take effect with a new game launch.
- **Per-game GPU drivers:** retain the global default and optionally select a
  game-specific driver. Resolution happens before renderer creation, with bounded
  content-identified extraction. Failed custom selection visibly falls back to
  the global choice or system driver; the effective outcome is logged.
