# Uberhar 0.1.26 — ordered Combo vertex dot products

<!-- CodexAstraLocal: Correct a reproduced mixed-route depth hazard without promoting a synthetic host result into a Dark Moon cure or throughput milestone. -->

Combo can draw depth with a generated GPU vertex shader and color with the CPU
JIT. Their dot products can round differently. A synthetic test using the
production x64 JIT, generated shaders, a verified 24-bit depth attachment and
LEQUAL reproduces complete color-coverage loss in both mixed-route orders.
The corresponding same-route controls retain full coverage.

This candidate gives Combo's optional GPU shaders explicit, precise pairwise
addition for DP4, DPH and DPHI when the CPU JIT is enabled. It preserves the
JIT's `(x + y) + (z + w)` rounding boundaries and the selected multiplication
sanitation. The policy is frozen with the renderer and retained in diagnostic
captures. Old 0.1.25 packets keep their legacy arithmetic when replayed.

DP3 remains unchanged because the two CPU JIT implementations differ at a
signed-zero edge. This is not general CPU/GPU numerical parity. Native, Custom,
OpenGL, JIT-disabled policy, draw admission and draw order retain their existing
behavior. No depth tolerance, draw omission, new worker or GPU wait is added.
Fresh CMake configuration is required to refresh the source-derived shader
cache identity.

The motivating host controls retain full coverage with precise arithmetic.
Host OpenGL SPIR-V execution repeats both optimizer policies; Vulkan modules
were validated, not executed. AArch64 source has
the same DP4/DPH addition tree, but executing x64 JIT and Mesa does not establish
Adreno behavior. The 0.1.25 private title captures have not identified a faulty
visible draw. Moon flashing and ghost corruption remain separate, unresolved
device targets; no Dark Moon fix or speed improvement is claimed.
