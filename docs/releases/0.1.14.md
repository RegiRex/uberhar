# Uberhar 0.1.14 — retain crash evidence and harden shader recovery

<!-- AstraEH: Reliability work after the accepted 0.1.13 audit discussion. -->

This build preserves independent session logs and removes a confirmed shader-worker
state hazard. **Dark Moon's graphical glitches and severe slowdown remain open.**
No renderer speedup or crash cure is claimed.

## Changes

- Each Android app process receives a timestamp-and-UUID session folder in private
  persistent storage. Its native log copy is independent of current/old/older rotation.
- Saved sessions remain until explicitly deleted. The log picker exports ZIP bundles
  with the log, build/session identity, title lifecycle markers, recorded errors and
  available Android exit evidence. Plain legacy text exports remain, including older.
- On API 30+, collect historical process exit reasons. Native tombstones are available
  on API 31+ when Android retained them. Distinguish confirmed crashes, ANRs, memory or
  signal exits, user exits and unknown interruptions. Filenames use OS exit time when
  known, otherwise explicitly use session start time; timestamps include UTC context.
- A real one-second scheduled flush handles quiet trailing records. The worker uses
  the existing bounded queue barrier; it does not block the UI or sync each frame.
  Archive export does not require a successful current-log flush. Storage/flush/size
  failures produce a warning; no automatic deletion of older evidence occurs.
- Generic shader jobs capture profile, optimizer, persistence and cache-path inputs
  before submission. Repeated disk-cache loading drains all generic module borrowers.
- The specific unavailable-recovery-shader error stops Android emulation through
  normal teardown and an explicit error dialog. It never skips a draw and resumes.
  Other native failures are not blanket-caught or claimed recoverable.
- Native symbol tables and Android deobfuscation mappings accompany releases.

Existing log cap is 100 MiB per file. Queued final records, power loss, app-data
clearing/uninstall and OS trace availability remain limitations. The private session
copies add disk writes; device overhead and Android crash survival require validation.
This version retains ordinary saved sessions too, with size display and explicit deletion,
so uncertain exits cannot silently discard evidence.

## Short test after the APK passes publication gates

1. Run a short familiar FEA or Sonic session, stop normally, and export the current
   session bundle. Confirm it opens and contains `log.txt` and session metadata.
2. Fully close/relaunch Uberhar a few times. The earlier saved bundle should remain
   selectable and exportable; title restarts inside the same process are not app restarts.
3. Continue normal testing. If a crash occurs naturally, relaunch and export that saved
   session bundle. Do not deliberately crash or run a long failing Dark Moon session.
   Stop at the first graphical anomaly when doing a short Dark Moon check.

The on-device settings editor is **planned by 2.0**, not included here. Its required
entry points are title long-press beside cache deletion and a submenu in the in-game
Uberhar settings menu. The broader audit experiments remain documented and deferred
until at least Dark Moon's graphical issues have been corrected and validated.
