# Uberhar 0.1.53

<!-- CodexAstraLocal: This release starts from original .48 graphics and selects small, separately attributable donors; build success is not a measured recovery. -->
This candidate returns to the original **0.1.48** rendering baseline
(`946a1bc4bcc023b768902aaebfb5200cd34e4015`) and adds selected CPU preparation,
full-fragment generation and correctness changes. It does not carry forward the
broad .49–.52 GPU optimization framework. Device performance is awaiting owner
comparison against .48; no recovery or speed gain is claimed before those runs.

- **CPU preparation:** reuse exact eligibility proofs, keep rejection bookkeeping
  on its owning thread, and start draw workers lazily. The original one-entry
  vertex mapping cache, small-work rejection, grouping and admission remain.
- **Optional CPU accounting:** **Collect detailed CPU worker counts** is off by default.
  Disabling it removes execution/peak-count atomics while retaining the resource
  admission and reservation operations needed for safe concurrency. A full app
  restart is required after changing it; logs identify requested/effective state.
- **Full fragment generation:** **Enable SPIR-V shader generation** now also
  selects the existing direct generator for compatible ready-full fragments.
  With it off, ready-full GLSL removes unused TEV and lighting work at generation
  time. Incompatible direct-generator configurations use the GLSL generator.
  Generic/static cold shaders and original admission limits remain unchanged.
  Restart the game after changing this setting. The setting was already present;
  Native/Combo now preserve its saved value instead of forcing it on.
- **Correctness:** end an old Vulkan pass using its old attachment metadata, and
  terminate failed timeline waits rather than repeatedly retrying terminal errors.
- **Compatibility:** preserve the current Native/Combo selection and saved-ID
  migration; selecting an original source baseline does not restore retired
  Android rendering modes. Existing application data is retained.

<!-- CodexAstraLocal: State GPU execution ownership and diagnostic limits explicitly. -->
Full fragment shaders still execute on the GPU. CPU shader generation/compilation
and CPU vertices are different from CPU pixel rendering. Direct SPIR-V versus
pruned GLSL is a useful generator comparison, not an isolated pruning on/off
experiment. Logs identify direct/GLSL build attempts without treating them as GPU
time or successfully selected draw counts. Existing route counters remain useful.

<!-- CodexAstraLocal: Preserve qualification gates and the owner's testing boundary. -->
The existing shader, Android, signing and publication gates apply. A passing build
produces a candidate for the owner's tests; no Thor installation, capture or
emulation test was performed for this release submission. The source review
covers ABI, immutable keys, worker ownership and retirement compatibility. The
ready-route fixture verifies dispatch with recording endpoints; it does not
establish direct-generator whole-game output. Hardware comparison remains needed.
