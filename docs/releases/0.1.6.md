# Uberhar 0.1.6 — reuse unchanged fragment uploads

<!-- AstraEH: Reduce repeated command recording after preparation reuse reached device. -->

## Evidence and decision

0.1.5 device logs show preparation-cache hit rates of 98.1–98.4% in FEA and
99.9959% in Sonic. Keep that optimization. Sonic's sustained normal selection
rises modestly from 61.793% to 63.520%, but different driving/scene timing and
existing driver-cache data prevent attributing the entire difference to code.
FEA 2x remains near full speed. Warm 4x has late 64%/59% windows despite only
43.266 ms total generic waiting; its slowdown is not repeated large compilation.

The next focused change suppresses redundant fragment push commands. It does
not assume every draw is redundant: actual byte changes always upload, and
new counters will establish the device reuse rate. Larger descriptor-command
changes and loading-time pipeline preparation remain separate work.

## Implementation

- Compare the complete 128-byte fragment block against the last successful
  generic upload on the command worker, after actual pipeline selection.
- Retain each queued draw's own constant copy. Specialized draws do not upload
  generic data and cannot incorrectly update the shadow value.
- Invalidate on command-buffer boundaries, title reset and foreign fragment
  writes from blits, filters and presentation. Process invalidation even if a
  specialized draw consumes the dirty notification before the next generic draw.
- Preserve pipeline binding, readiness/failure recovery, descriptor binding,
  shader arithmetic, fragment ABI 7, draw order, disk caches and driver workarounds.
- Add ordered progress/final counters for requests, uploads, exact reuses,
  invalidations and logical bytes avoided. No per-draw clocks, atomic statistics
  or new reporting waits. Renderer diagnostics become 17; frame schema stays 3.
- Maintain AstraEH comments and the code map. Existing automatic settings/cache
  diagnostics and normal-speed filtering remain available.

## Validation and limits

The production helper passes a queued command-state model with 175223 selected
generic draws, 14890 uploads and 160333 exact reuses. Directed tests mutate all
128 ABI bytes, exercise upload failure/retry, alternate selected pipeline paths,
interleave foreign partial writes and compute/descriptor operations, start fresh
command buffers, and reset after a drained title switch. This verifies exact
command-state behavior, not device pixels or a real workload's hit rate.

Local host suite, address/undefined-behavior sanitizers and syntax checks of the
pipeline cache, scheduler, blit and presentation integration pass. Shader headers
for syntax checks are produced by the repository's real generator. Shader math
and transport bytes are unchanged; required shader/pixel/Vulkan, Android build,
package, signing and prerelease publication gates run in Actions and remain
pending at handoff. Thor performance/visual acceptance is still required.

Fewer push commands do not guarantee an FPS gain: the driver may already make
identical uploads cheap, while byte comparison adds a small host cost. Logical
saved bytes are not measured GPU bandwidth. Counters record actual worker work,
so progress can lag nearby renderer-thread totals. Final snapshots are drained.

## Next test

Use familiar FEA 2x/4x scenes and a Sonic 2x race. A short Smash/Samus effects
check is useful for this command-state change when convenient. Watch for stale
lighting, alpha, fog, texture effects or new hitches, especially after menus,
pause/resume or title changes. No need to transcribe resolution/cache settings.

Incidental fast-forward remains excluded. Unattended time within an active run
cannot be confidently removed without a marker; time between closed sessions
already lies outside run totals. Short scene/idle notes remain helpful but are
not a reason to require repeating an otherwise useful test.
