# Uberhar 0.0.7

Android ARM64 experimental alpha for Ayn Thor. After the build and publication
gates pass, install **uberhar-0.0.7-arm64.apk** over Uberhar. Application identity,
log export, signing continuity and package validation remain in place.

## Why this update

The owner's 0.0.6 cold Awakening capture records 18.849 seconds of scheduler
pipeline waits, while its warm session records none. Only 9 of 52 compiled
fallback pipelines served draws. The unused 43 consumed 8.960 seconds of driver
creation wall time, overlapping other work. That time cannot simply be subtracted
from the gameplay waits.

The [full architectural review](../UBERHAR_ARCHITECTURE_2026-09-24.md) concludes
that ready generic programs, vertex independence and Vulkan pipeline coverage
are needed for smoother first encounters. The existing on-demand fragment fallback
cannot guarantee that. This version implements the first foundation and adds
measurements to choose the next stage; it is not the whole new renderer.

## Changes

- **Consolidate equivalent fallback fragment families.** After applying the
  device profile, normalize native sampler requests, shader-irrelevant blend
  requests, inactive logic requests and disabled fog orientation. These choices
  were verified to produce identical shader source. Native sampler and complete
  pipeline state still retain their actual values, including blending.
- **Preserve shader-affecting distinctions.** Active emulated border checks,
  active fog orientation, shader-emulated logic, alpha tests and typed texture
  interfaces stay distinct. The helper does not alter the input configuration or
  transferable cache layout. Live TEV instructions remain per-draw data.
- **Log the candidate state space.** `Uberhar variant census` reports raw and
  canonical fragment families and pipeline combinations, vertex/geometry IDs,
  layouts, attachments, blending, rasterization and depth/stencil. It samples
  eligible fallback requests before admission limits, including deferred work.
  Each dimension is bounded to 2,048 distinct keys. `capped=true` means counts
  are lower bounds. These are per-title candidates, not actual build counts;
  independent dimension counts must not be multiplied into a coverage estimate.
- **Record architectural review cadence.** Review every three to five alpha
  builds, normally four. This review covers 0.0.6; the next is due around 0.0.10.
  New implementation sections are attributed to AstraEH and indexed in the code map.

The startup line identifies `diagnostics=4 canonical_tev=true`. Existing wait,
build, size and fallback-utility counters remain. Ready specialized draws in
normal hybrid mode do not enter the new canonicalizer or census. Forced mode
intentionally requests fallbacks and therefore does.

The one-in-flight normal fallback admission policy, cache caps, specialized path,
shader support exclusions and first-ready scheduling are retained. No Android
permissions, runtime dependencies or Vulkan extension requirements are added.
This does not enable a driver workaround that Azahar had disabled.

## Validation and limits

The new host regression probe passes **6,160 source-equivalence and idempotence
checks**, covering **2,856 pairs that should merge** and **224 shader-affecting
pairs that must remain distinct**. The existing 64 full fragment cases now pass
through the production canonicalizer and are checked against their original
generated source before Vulkan validation.

The complete local shader suite passes **128 Vulkan module validations** with
frontend optimization off/on, **57,344 exact RGBA8 comparisons** across 224 TEV
programs, and **57,344 texture-fetch checks**. Eight manifest regression tests and
the 161-key Android settings check also pass. These host checks do not measure
Thor speed, real texture derivatives or whole-game rendering correctness.

Android compilation, completion tests, repeat shader tests and final APK manifest,
ABI, native-library, alignment and signing checks must pass in GitHub Actions
before publication. Device performance is not yet measured. Some distinct native
pipeline states still need separate pipelines even when their fragment module is
shared. First-use compilation waits remain possible.

The inherited source fingerprint may regenerate cached frontend programs after
this update. Existing observations and compatible driver cache entries remain
reusable; an initial regeneration is not itself an in-game performance result.

## Device comparison

1. Keep the same driver, **2x resolution**, **Hybrid TEV on** and **Force TEV
   fallback off** for comparison with the supplied 0.0.6 log.
2. Exit to the game library. Long-press Awakening, choose **Delete Shader Cache →
   Vulkan → OK**, and clear only before the first run.
3. Play the same section at normal speed and exit through the emulator menu.
4. Replay it with the cache retained and the same settings, then exit normally.
5. Save the **Current session** log. Note visible pauses or rendering changes.

Test 4x resolution and fast forward separately after this comparison. Normal
hybrid mode is the performance target; forced mode is a separate correctness
experiment. The new census will show whether source-equivalent family reduction
matters in this game and which remaining state dimensions dominate.
