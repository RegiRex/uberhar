# Uberhar 0.1.56

<!-- CodexAstraLocal: Preserve the .55 renderer baseline while reducing redundant depth-cache work and exposing controlled Azahar comparisons. Hardware gains remain to be measured. -->
This candidate avoids marking read-only Vulkan depth/stencil attachments as written,
adds identifiable sampled GPU-pass costs, and exposes per-game rendering comparison
controls. It also incorporates the reviewed upstream installer-safety and encrypted
file-compatibility ports. Existing Native/Combo defaults remain in place.

- **Read-only depth handling:** after resolving the current attachment format,
  draws that cannot write depth or stencil retain the existing cached depth contents.
  Color invalidation, real depth/stencil writes, masked stencil behavior, aliases
  and canceled-draw handling remain intact. This removes unnecessary invalidation;
  counters measure actual helper exits, not inferred GPU time saved.
- **GPU-cost attribution:** the existing sparse timestamp ring retains bounded
  frame/pass, guest-target and fulfilled pipeline/shader identities. A bounded
  representative sample distinguishes mixed-pipeline passes from single-pipeline
  passes. Pass-end causes help identify submission, feedback-copy and state-change
  boundaries. No extra GPU completion wait or diagnostic render-pass split is added.
  Timings still include dependencies and do not measure pure shader cost, complete
  frame time or physical memory bandwidth.
- **Per-game Testing:** add Hardware Shaders, Delay Game Render Thread, Linear
  Filtering, guest 3D slider 0%/1%, and Disable Right Eye Render. Defaults preserve
  ordinary hardware acceleration OFF, delay0, filteringON, slider0 and suppressionOFF.
  Controls apply at next launch; the existing resolution shortcut remains live.
  Combo CPU Vertices ON keeps both ordinary and ready GPU-vertex admission disabled.
- **Hardware experiment correctness:** ordinary hardware input retains its translated
  vertex/geometry stages through generic fragment fallback. Native/Combo pipeline
  refusal retries CPU processing rather than accepting an omitted draw. Actual
  ordinary GPU enqueue counts distinguish execution from permission or no-op calls.
- **Usable settings:** the Testing header scrolls with the rest of per-game Settings.
  Graphics/Debug show effective profile values without overwriting saved Custom values.
  Beta/full versions hide Testing and ignore stale overlays; per-game driver selection
  remains available. Useful experiments will move to ordinary settings or defaults,
  and unsuccessful controls and their exclusive diagnostics will be retired.
- **Installer safety and file compatibility:** port the pinned Azahar installer
  bounds/ownership fixes and selected Azahar Plus encrypted NCCH/CCI/CIA and RomFS
  handling. Supplied-key facilities remain unchanged; no keys or seeds are included.
  Staged installation validates content and finalization before promotion, preserving
  recovery data on failed rollback. Generic ZIP/7z support is not part of this change.
  See [compatibility provenance and boundaries](../UBERHAR_FILE_COMPATIBILITY.md).

Hardware Shaders OFF does not disable Combo's independent ready-GPU route when
CPU Vertices is OFF. Full fragment shaders still execute on the GPU. The new
hardware control is an explicit placement experiment rather than a changed default.
The guest slider reaches the game even with mono presentation; 1% may change guest
behavior without enabling stereo display. Linear Filtering controls final screen
presentation, not guest texture filtering. Render-thread delay affects the guest
IPC response schedule, not a new host worker or measured GPU delay.

For the next owner comparison, hold driver, resolution, cache treatment and scene
constant. Compare each new control independently before combining helpful changes.
Separate Xenoblade opening cinematic, battle cinematic and gameplay; retain the
usual low/high CPU/GPU context and all-core chart. Designated warm comparisons
supplement the cold-cache complete-output goal.
