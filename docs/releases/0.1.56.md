# Uberhar 0.1.56

<!-- CodexAstraLocal: The second same-version repair corrects precedence without replacing original or r1 release artifacts. -->
The `0.1.56-r2` precedence repair keeps app version **0.1.56** and preserves the
original `0.1.56` and `0.1.56-r1` tags and artifacts. Options now edits global
defaults exclusively, including every Testing control. Ordinary per-game settings
override global Testing defaults, and each game owns its Testing switch and
explicit Testing choices. Saving one choice preserves inheritance for the rest;
confirmed reset removes only the selected scope's overrides. The r1 Settings crash
fix and scrolling Testing header are retained.

<!-- CodexAstraLocal: State the full precedence and real conflicts rather than promising per-game wins only inside testing.ini. -->
Settings resolve in this order: ordinary globals, explicit global Testing defaults,
ordinary title settings, then explicit title Testing choices. Only actual model
conflicts apply afterward. All eight Testing keys—including enabled—are scoped;
even an ordinary title selection equal to its displayed value persists explicitly,
including OFF and zero. Disabling Testing for one title leaves other titles alone.
Options never becomes a running-title editor. Rendering resources remain fixed
during a game; resolution stays adjustable.

<!-- CodexAstraLocal: Preserve the .55 renderer baseline while reducing redundant depth-cache work and exposing controlled Azahar comparisons. Hardware gains remain to be measured. -->
This candidate avoids marking read-only Vulkan depth/stencil attachments as written,
adds identifiable sampled GPU-pass costs, and exposes per-game rendering comparison
controls. It also incorporates the reviewed upstream installer-safety and encrypted
file-compatibility ports. Unconfigured Native/Combo baselines remain in place;
explicit independent saved preferences are now honored instead of silently replaced.

- **Read-only depth handling:** after resolving the current attachment format,
  draws that cannot write depth or stencil retain the existing cached depth contents.
  Color invalidation, real depth/stencil writes, masked stencil behavior, aliases
  and canceled-draw handling remain intact. This removes unnecessary invalidation;
  counters measure actual helper exits, not inferred GPU time saved.
- **GPU-cost attribution:** the existing sparse timestamp ring retains bounded
  frame/pass, guest-target and fulfilled pipeline/shader identities. A bounded
  representative sample distinguishes mixed-pipeline passes from single-pipeline
  passes. Pass-end causes help identify submission, feedback-copy and state-change
  boundaries. No extra GPU completion wait or diagnostic render-pass split is added.
  Timings still include dependencies and do not measure pure shader cost, complete
  frame time or physical memory bandwidth.
- **Global/per-game Testing:** add Hardware Shaders, Delay Game Render Thread, Linear
  Filtering, guest 3D slider 0%/1%, and Disable Right Eye Render. Unconfigured
  Native/Combo defaults preserve ordinary hardware acceleration OFF, delay0,
  filteringON, slider0 and suppressionOFF. Saved ordinary title choices defeat
  global Testing defaults; explicit title Testing choices can override that title's
  ordinary values. Missing Testing fields add no override. Custom retains its
  ordinary Hardware Shaders default, and invalid ordinary hardware entries inherit
  before using the final mode's default.
  Controls apply at next launch; the existing resolution shortcut remains live.
  Combo CPU Vertices ON keeps both ordinary and ready GPU-vertex admission disabled.
- **Hardware experiment correctness:** ordinary hardware input retains its translated
  vertex/geometry stages through generic fragment fallback. Native/Combo pipeline
  refusal retries CPU processing rather than accepting an omitted draw. Actual
  ordinary GPU enqueue counts distinguish execution from permission or no-op calls.
- **Usable settings:** the Testing header scrolls with the rest of per-game Settings.
  Blanket graphics/profile locks are removed. Ordinary rows edit saved preferences;
  Testing displays resolved choices without overwriting Custom files. Genuine
  conflicts show their enforced value and reason: Combo CPU Vertices ON excludes
  hardware vertices, and an explicitly chosen Native/Combo profile requires Vulkan.
  A title inheriting a global profile can select its own non-Vulkan backend and
  resolve to Custom. Independent filtering, cache, texture, stereo and shader-JIT
  choices are honored. Complete-draw and launch-resource safeguards remain intact.
  Beta/full versions hide Testing and ignore stale overlays; per-game driver selection
  remains available. Useful experiments will move to ordinary settings or defaults,
  and unsuccessful controls and their exclusive diagnostics will be retired.
- **Installer safety and file compatibility:** port the pinned Azahar installer
  bounds/ownership fixes and selected Azahar Plus encrypted NCCH/CCI/CIA and RomFS
  handling. Supplied-key facilities remain unchanged; no keys or seeds are included.
  Staged installation validates content and finalization before promotion, preserving
  recovery data on failed rollback. Generic ZIP/7z support is not part of this change.
  See [compatibility provenance and boundaries](../UBERHAR_FILE_COMPATIBILITY.md).

<!-- CodexAstraLocal: Explain actual work placement and the useful next comparison, without claiming performance from a setting label. -->
Hardware Shaders OFF does not disable Combo's independent ready-GPU route when
CPU Vertices is OFF. Full fragment shaders still execute on the GPU. The new
hardware control is an explicit placement experiment; the unconfigured profile
default remains OFF while explicit saved hardware choices are honored.
The guest slider reaches the game even with mono presentation; 1% may change guest
behavior without enabling stereo display. Linear Filtering controls final screen
presentation, not guest texture filtering. Render-thread delay affects the guest
IPC response schedule, not a new host worker or measured GPU delay.

For the next owner comparison, hold driver, resolution, cache treatment and scene
constant. Compare each new control independently before combining helpful changes.
Separate Xenoblade opening cinematic, battle cinematic and gameplay; retain the
usual low/high CPU/GPU context and all-core chart. Designated warm comparisons
supplement the cold-cache complete-output goal.

<!-- CodexAstraLocal: Hosted build/signing and actual handheld output remain independent acceptance steps. -->
Affected executable fixtures, Android settings/resources and pinned ARM64 source
checks precede submission. The existing shader, Android, signing and publication
workflow remains required. No hardware performance improvement or installation/
whole-game compatibility is asserted before owner qualification. Package identity,
signing pin, saves and normal driver baseline are unchanged. Broader render-pass
containment, feedback-copy reuse and draw grouping remain follow-up candidates.

The initial Android build exposed a private installer Crypto++ dependency through
the shared AM header. The repair keeps verifier destruction in the core implementation
and adds an early Android header/ownership compile check before the full build.
It does not change installer behavior or rendering. Publication still requires
the full Android, shader, signing and packaging gates to pass.
