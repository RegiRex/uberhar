# Uberhar 0.0.4

Android ARM64 alpha with a new **Options → Save or Share Log** picker.
Install **uberhar-0.0.4-arm64.apk** over your existing Uberhar installation.

Choose **Current session** or **Previous session**. The picker shows each log's
date, detected games and recorded build, then previews the proposed filename.
Select either **Word initials** or **First 3 characters**, then:

- **Save to file** opens Android's file picker so you can save to Downloads or
  another location. You can edit the suggested filename there.
- **Share** opens Android's sharing menu with the same named text file.

Examples:

```text
uberhar_log_9_24_0100_FEA.txt
uberhar_log_9_24_0100_FIR.txt
uberhar_log_9_24_0100_FEA_TLOZOOT3D_MK7.txt
```

Dates use the recorded session's local month/day and 24-hour time, without a colon
in the filename. Numeric words such as `3D` and `7` remain intact. Replaying the
same game does not repeat its abbreviation. Single-word titles use up to three
characters; shorter titles use what is there. Games remain in first-play order.

The old sharing code relied on a flag that was never updated, so it could select
the previous log after a new game run. Selection is now explicit. Current logs
are flushed before export and copied into a fixed snapshot so a later app restart
cannot change the selected download. Cancelled exports preserve the source logs.

Older logs use their recorded file modification date and game filenames when
they lack the new metadata. Missing dates/games are clearly marked; non-Latin-only
titles use `GAME` in the portable filename. Very long lists end with `_PLUSn` to
stay within filename limits; the log itself is not truncated. Identical download
names are handled by Android's file picker, while shared copies use distinct
private staging directories.

No additional Android permissions are requested. Sharing grants read access only
to the selected copy through a private provider scoped to log exports. Temporary
export copies older than seven days are cleaned when preparing a new export.
Source logs, shader caches, settings and saves are not deleted by this feature.

The renderer and shader cache format are unchanged from 0.0.3. Keep **Hybrid TEV
on** and **Force TEV fallback off** for the ongoing Awakening performance test.
This update makes collecting the test logs easier; it adds no shader speedup.

Validation includes Android compilation, production parser/filename JVM tests,
shader comparisons, installation checks, provider configuration, ARM64 dependency
checks, alignment and continuity of the existing signing certificate. Actual
Android picker/share-target interactions still need device testing.
