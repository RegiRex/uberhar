## Test

Use **Native at 2x**. Clear Vulkan cache once, run the same section including a battle,
exit normally, then repeat without clearing and export the log. No extra overlay
setting is needed. If called away, pause the emulator so the interruption is marked.
If a visual issue appears, a screenshot and your description remain useful.

## Interpretation limits

These are emulator frame-end timings, not Android panel presentation or exact
top/bottom-screen synchronization measurements. Work time is wall time and can
include waits; it is not CPU utilization or GPU execution time. Game FPS counts
guest submissions, not distinct images reaching the panel. A first interval and
intervals crossing explicit pauses/state loads are excluded, with counts logged.
Windows can include menus and unattended gameplay; no battle or human-absence
detector is claimed. The frame cap ranges identify emulator fast forward, not a
game's own acceleration feature. Final records require normal shutdown.

Battery temperature is not CPU/GPU temperature. Platform thermal reporting may be
incomplete, so a zero status cannot prove no throttling. Native heap allocation is
not total process RAM. Missing readings stay unknown. These bounded records cover
current optimization questions; later problems may need targeted instrumentation.

## Validation

Synthetic production-counter tests cover frame/speed arithmetic, histogram edges,
fast-forward changes, ten-minute pause exclusion, window reset, clock/guest-time
discontinuities and late worst-hitch retention. Host syntax checks cover performance,
renderer and core-loop integration. All 163 Android keys and eight manifest checks
pass. Android compilation and runtime behavior remain
subject to Actions validation and device testing; no performance improvement is
claimed from this diagnostic update.
