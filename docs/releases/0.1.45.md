# Uberhar 0.1.45 — CPU texture workers and renderer corrections

<!-- CodexAstraLocal: Describe useful parallel work without claiming an unmeasured speedup or fixed CPU utilization requirement. -->
Native and both Combo presets can now decode large, complete tiled texture
uploads across CPU workers. Workers reuse the existing pixel codecs and write
distinct tiles; the owner joins them before uploading or publishing the texture.
The initial threshold is 32,768 pixels. The decoder's participant allowance is
the calling thread's available CPU count minus two, with a minimum of one. This
is a local worker budget, not physical-core reservation or a global thread cap.
Small, partial, linear, depth/stencil or concurrently writable uploads retain
serial CPU decoding. No new GPU work or draw skipping is introduced.

<!-- CodexAstraLocal: Keep the owner's requested controls visible and independent of preset application. -->
Three controls appear immediately below **Use CPU vertices in Combo** in Graphics:

| Control | Default | Effect after restarting the game |
|---|---|---|
| Native full fragment shaders | On | Off isolates Native's optional full fragment specialization; Combo policy is unchanged. |
| Overlap CPU vertex assembly | On | Off keeps parallel vertex shading but waits for its complete join before assembly. |
| Parallel CPU texture decoding | On | Off uses the existing serial upload codec. |

CPU Vertices remains a separate Combo placement choice. Native already executes
guest vertices on the CPU. The two existing optimizations retain their .44
defaults; the texture decoder is the new performance experiment. Intermittent
moon/title-smoke observations remain recorded, but recent owner repeats did not
reproduce them. These controls support future isolation without declaring a
confirmed cause or requiring another visual test now.

<!-- CodexAstraLocal: Tie the Software correction to its actual numerical witness and preserve the distinct unresolved FEA input. -->
CPU Software now applies top-left edge bias only to pixel coverage. Attributes,
helper coordinates and depth use unbiased interpolation weights. This addresses
the captured area-one Dark Moon triangle whose biased weights incorrectly
collapsed to zero. Exact zero-area triangles exit before interpolation. A
separate FEA invalid-coordinate fault remains unproven; bounded first-failure
logs retain original and prepared operands rather than inventing valid samples.

<!-- CodexAstraLocal: State the exact supported Calculated correction and avoid implying that every recorded clipping failure shares it. -->
Calculated handles an original homogeneous-zero vertex as a zero-filled-area
triangle while preserving other triangles and semantic carry. Arbitrary
nonprojectable geometry still fails explicitly. Clipping diagnostics distinguish
nine failure reasons and capture bounded operands in the existing status buffer.
This remains independent compute rendering with no Native fallback. Successful
gameplay on the Thor is still required to establish usability.

<!-- CodexAstraLocal: Make temporary measurements interpretable and removable. -->
Sampled texture logs report whole decode-call wall time, owner work, worker tiles
and join time at bounded intervals. These are not aggregate worker CPU time or
frame speedup. New temporary diagnostics carry `CodexAstraLocal TEST-ONLY LOG`
markers and removal conditions. Existing vertex-phase, cache and allocator
measurements remain available; no duplicated memory sampler is needed.

<!-- CodexAstraLocal: Keep source validation, release qualification and real device performance separate. -->
The consistent native build, settings matrix, 68 exact-output texture cases,
ordered-prefix controls and two Software cases (38 assertions) pass. Five
Calculated geometry groups match complete reference color/depth output with
byte-centered fixture colors; three deliberate defects are detected. A separate
valid midpoint-color case still differs by one green-channel value at 17 pixels,
with matching coverage/depth/stencil. That precision discrepancy is retained and
unfixed; it is not waived as universal parity. The
[architecture and purpose review](../UBERHAR_REVIEW_0.1.45.md) records final scope.
The existing shader, Android, signing and publication gates remain mandatory.
Hardware testing belongs to the owner after build submission; no 99% speed,
three/four-core utilization or 4x performance result is claimed by this release.
