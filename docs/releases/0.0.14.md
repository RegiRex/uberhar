# Uberhar 0.0.14 — fewer lighting variants

<!-- AstraEH: Runtime lighting-enable/configuration consolidation after the 0.0.13 Thor result. -->

This alpha targets the remaining cold lighting compilations. **0.0.13 Native at
2x remains the measured reference**: 2.948 s cold generic waiting and 99.776%
fully warm emulation speed. Its worst cold frame contained three separate slow
generic builds. 0.0.14 aims to share more of those programs; the Thor speedup and
warm-performance cost remain unmeasured until device testing.

- Move LUT enables and lighting-configuration support into the existing per-draw
  control bytes. These choices can share one program rather than splitting families.
- Return early for disabled LUTs, preserving default distribution/spotlight values,
  green/blue reflection's red-channel fallback, and final-light Fresnel alpha.
  Preserve the zero index used by CP inputs outside Config7 and spotlight's
  per-light enable semantics. Light count, directional/positional operations,
  geometry factors, bump/shadow structure and the CPU vertex route remain specialized.
- Keep the push-constant transport at **120 bytes**, with semantic ABI version 4.
  Source/build fingerprints separate incompatible cached modules. Accurate recovery,
  rendering order, driver workarounds and existing pipeline admission caps remain.
- Add `alpha13_families` beside current and 0.0.12 family counts for the **same
  observed draws**. Record at most 32 successfully built family shapes per title
  to identify the next sources of specialization. No new per-draw log text or timer.
- Correct the ambiguous core header: `frame_diagnostics=1` is independent of
  renderer `diagnostics=11`. Timings are unchanged. New troubleshooting calls
  retain searchable `AstraEH Log Line` comments; new implementation sections use
  the requested `AstraEH` attribution.
- Expand full fragment comparisons from 416 to 928 cases, including all 64 real LUT
  enable masks crossed with all eight configurations. Both Vulkan frontend optimizer
  modes, pixel comparisons and the existing ARM64 package/signing gates are required
  for publication.

## Test

Use **Native at 2x** and the same battle section. Clear Vulkan cache once, run cold,
exit normally, then repeat without clearing for a warm run. If the warm run introduces
an extra ally attack, make a third warm pass as before. Export one log after the runs;
note any visual changes, sustained battle slowdown or long individual pauses.
Pause emulation if called away. No additional settings or driver download are needed.

An old-version warm cache is not a fully warm 0.0.14 cache. Custom hybrid/forced TEV
also use the new programs. Compute coverage has not expanded; Native alone is the
useful comparison for Awakening at this stage.

## Limits and acceptance

Fewer programs can still mean larger individual programs and additional uniform
branches. Device evidence must show whether the cold reduction outweighs this cost
and preserves 0.0.13's warm speed and image quality. Some native pipeline states,
structural lighting, procedural effects and unsupported fragment paths still require
compilation. This release does not claim compilation-free first playthroughs.
Host agreement checks the inherited specialized renderer, not complete 3DS hardware
accuracy or Adreno behavior. Frame timings do not measure physical display alignment.

No Android permissions, package identity, dependencies, signing policy or external
services change. This is the second alpha after the review covering 0.0.12; the next
full review remains due by default after 0.0.16 (allowed 0.0.15–0.0.17). Screen
synchronization and model clarity remain later roadmap work.

## Local validation

9,448 family/source/idempotence checks pass, including the independent support
matrix and retained structural distinctions. The existing 57,344 exact TEV RGBA8
comparisons and 57,344 texture-use checks pass. All **1,083 distinct complete Vulkan
programs** compile and pass SPIR-V validation with optimization off and on (2,166
validations), including the TEV loop hint and all seven push-constant offsets.
Production host probes, Vulkan/core integration syntax, all 163 Android setting
keys, eight manifest-policy checks and formatting/whitespace checks pass.

**950,272 exact RGBA8 pixels** and 950,272 depth/discard comparisons match the
specialized renderer across all 928 cases on Mesa llvmpipe. These are host results;
Thor rendering and performance remain to be tested.

Full Android compilation and APK/signature verification run in Actions, which also
repeats the shader gates. The APK is published as a prerelease only after every
required gate succeeds.
