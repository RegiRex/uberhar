# Uberhar 0.1.0 — Native beta and vertex headroom

<!-- AstraEH: Owner-endorsed beta milestone, with a measured baseline and testable CPU changes. -->

The owner reports no noticeable gameplay slowdown in four 0.0.15 Fire Emblem
Awakening runs on AYN Thor at 2x. Normal cold/warm speed averages 98.858/99.795%;
fast-forward portions average 283.379/292.518% under a 400% cap. Cold generic waiting
falls from 3.298 to 0.662 seconds versus 0.0.14. Those results support **0.1.0**,
the first beta of the Native path. Early cold hitches remain; this is not a claim
of universal compatibility or zero compilation in every title.

## What changes

- **Prepare vertex transport once per draw.** Predecode the input-register mapping
  and compose the output-mask/semantic mapping, preserving defaults, duplicate
  assignment order, output banks and pre-interpolation color saturation.
- **Reuse final vertices.** Indexed cache hits reuse a 96-byte converted vertex
  instead of copying a 256-byte attribute buffer and converting it again. In the
  measured normal tests, about 64.8% of vertex inputs were cache hits. This is an
  opportunity to remove work, not a promised 64.8% overall speedup.
- **Keep exact execution and assembly.** Retain the 64-slot FIFO, every submitted
  vertex, shader invocation order and partial primitives across draws. GS,
  debugging, Custom mode and incomplete mappings retain the established path.
- **Expose the next CPU bottleneck.** A rotating vertex sample separates input,
  shader execution, output conversion and triangle submission. Sampling is limited
  to one vertex per 128 eligible batches, at most 8192 samples per title; reports
  share the existing five-second/shutdown cadence. Ordinary batches have no new
  per-vertex clock reads. These are sparse CPU wall-time samples, not GPU timings.
- **Identify the milestone.** App label becomes Uberhar Beta, version 0.1.0.
  The existing package, data-folder location, update signing and installation gates
  are retained. No Android permissions, dependencies or external services are added.

The successful compact runtime fragment path, ABI 5, native pipeline keys, driver
workarounds and failure recovery are retained. No screen-sync or general compute
improvement is claimed by this release. All new sections are attributed AstraEH;
debug calls carry searchable `AstraEH Log Line` comments.

## Test on Thor

Install the ARM64 APK as an update. Keep **Native, 2x resolution** and the same scene:

1. Clear Vulkan cache; run normally at 100% (cold).
2. Repeat at 100% without clearing (warm).
3. Clear Vulkan cache; run with emulator fast-forward capped at 400% (cold).
4. Repeat fast-forward without clearing (warm).

Exit normally after each run, then export the combined log. Note any visual change,
extra ally attack, pause or sustained slowdown. Pause when stepping away. Keep
0.0.15's test conditions for this comparison; assess 3x and 4x afterward in separate
normal-speed runs. The first run after an update may not reuse old module-cache
fingerprints even if the driver cache is still present.

## Goals and review

Preserve smooth, accurate cold gameplay; increase sustained headroom; work toward
full-speed 4x; expand runtime coverage; then improve matched dual-screen delivery
(Kid Icarus acceptance) and model clarity. Compute and GPU vertex interpretation
remain research paths whose adoption requires correctness and useful coverage.

The [complete architecture review](../UBERHAR_ARCHITECTURE_0.1.0.md) evaluates source,
all four runs, alternatives, limits and acceptance criteria. It resets the review
ledger after three alphas. Count this beta as the first successor; next default
review is after 0.1.3, allowed 0.1.2–0.1.4, before 0.1.5.
See the [device analysis](../UBERHAR_LOG_ANALYSIS_0.0.15.md) and
[diagnostic definitions](../UBERHAR_DIAGNOSTICS.md).

## Validation and availability

Host comparison passes **998,282 bitwise vertex-output checks**, covering all 65,536
output masks, both output banks, semantic collisions/overflow/defaults, exceptional
float values and input mapping. **384 FIFO/assembly batches** cover eviction,
collisions, non-indexed full-width offsets, all four topologies, winding,
cross-draw partial primitives, and sampled/unsampled parity. Address/undefined
behavior sanitizer checks pass; leak scanning is unavailable in the host sandbox.
PicaCore integration syntax and the existing production host probes pass, including
11,472 shader family/source checks, one million FIFO reference comparisons and
30,000 interpreter invocations. Mesa llvmpipe also matches **1,081,344 exact RGBA8
pixels** and as many depth/discard comparisons across the existing **1,056 full
fragment cases**. All 163 Android setting keys and eight manifest-policy tests pass.
These are host checks, not ARM64/Adreno performance evidence.

Android ARM64 compilation, shader/pixel regression, APK identity/manifest/native
library/alignment and pinned-certificate checks remain mandatory Actions gates.
Publication is automatic only after every gate succeeds, as a GitHub prerelease.
Development hands off the build without waiting through compilation. The new CPU
path has **no Thor performance result yet**; retain 0.0.15 as the device reference.
