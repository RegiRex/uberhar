# Uberhar 0.1.35 — ordered multicore CPU vertices

<!-- CodexAstraLocal: Describe the candidate's useful work and exact-rendering
boundaries without treating created threads or host replay as a Thor speed gain. -->

Native and the CPU portion of Combo can distribute independent vertex-shader
invocations across the processors available to the process. Persistent sleeping
workers and the calling thread share batches of actual FIFO misses. Input loading,
the existing JIT and output conversion run on disjoint results; the calling thread
retains exact FIFO discovery and submits every vertex in its original order.
Scratch storage is bounded per draw and available processor count. No transformed
vertex cache survives the draw, and this does not skip guest draws.

An acyclic control-flow and register-definition certificate admits only shaders
whose required temporary, address, condition and output state cannot depend on a
previous invocation. Complete arithmetic operand lanes are checked, including
lanes discarded by SIMD output masks. Unsupported control flow and state carry
retain serial execution. Exact-index rescues, geometry shaders, debugger/timing
observers, enabled floating-point traps and platforms without a validated full
floating-status adapter also retain their existing serial paths. Actual threaded
DSP, scripting RPC and pending asynchronous guest-memory writers prohibit worker
reads. Live settings are not used as a substitute for constructed engine state.

The pool adapts to the process's allowed CPU count; it has no fixed eight-core
limit. After FIFO discovery, fewer than 256 real shader invocations stay on the
owner because representative small host replays regressed with worker wakeups.
The ordinary report distinguishes available/created/working threads, actual
owner/worker invocations and admission refusals. These counters do not measure
CPU utilization, throughput or complete-title parallel coverage.

<!-- CodexAstraLocal: Tie the compiled artifact to the proof's actual source and

Proof storage uses eight exact program snapshots with sixteen control-state
entries each. ShaderSetup source revisions invalidate the current binding on
uploads, assignment and save-state restoration. Copies retain guest fields but
clear imported compiled bindings. The JIT cache now also compares exact source
bytes within hash buckets and compiles from retained owner snapshots; a hash
collision cannot bind different code than the certificate examined. Two live
setup bindings avoid full comparisons on unchanged draws. Each compiled program
retains an additional 32 KiB of source identity; this is host memory, not a saved
application shader cache.

<!-- CodexAstraLocal: Explain the reproduced ARM return failure and narrow repair,
without assigning an unproved title anomaly or changing shader arithmetic. -->

ARM64 guest CALL return boundaries now use a preserved register instead of a
stack-relative location whose contents depend on caller and helper frames. The
original implementation returned with an incorrect stack pointer in a controlled
execution case. The correction preserves nested boundaries, caller registers,
stack-frame sizes and existing shader arithmetic. This matters for safely calling
the same compiled shader from worker threads with different caller state.

Focused host controls cover exact FIFO/assembly order, source invalidation,
collisions, save restoration, floating state and failure cleanup. Real ARM64
execution under QEMU covers return/ABI behavior and concurrent shared JIT calls.
The Android workflow runs that NDK/QEMU gate before building the app. The final
native build and CTest pass with the five existing firmware-dependent skips.
All host-probe stages pass; a retained source-stability interruption during the
copy fix was followed by repeated affected stages and the complete remainder.
Independent architecture and separate cleanliness reviews found no remaining
source blocker. Release/signing gates and Thor Native/Combo runs are pending.

The ordered-batch gate covers 1,872 draws and 5,536,944 inputs. The certificate
gate covers 585 cases, 299,136 real backend comparisons and 120 composed draws,
with nine intentional defects detected. Final ARM64 execution covers twenty
programs, 4,480 JIT calls, eighty concurrent shared-JIT jobs and 738 pool jobs;
return and floating-status defects fail their required assertions. These are
bounded synthetic contracts, not a claim of universal shader correctness.

Private warm x64 replays using the final bound call and batch policy measured
parallel/serial time ratios of 0.7284, 0.6005 and 0.5414 with two, four and eight
available participants on a retained 723-invocation draw. The 142/168-invocation
draws remain owner-only after the cutoff and measured about 0.91. The harness
includes prepared inputs, FIFO, actual JIT, conversion and primitive assembly;
it excludes full Pica setup, renderer submission and Thor conditions. It does not
predict complete-title throughput. Calculated's independent triangle work remains an isolated
prototype and is not included in this candidate. Sustained 99% normal speed,
4x resolution and broader gameplay remain unqualified.
