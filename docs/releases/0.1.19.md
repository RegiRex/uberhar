## Changes

- Selected periodic renderer/vertex/shader-cache progress records use nonblocking
  queue admission. Full queues and producer-lock contention can omit these optional
  snapshots instead of holding their emulation/render thread.
- Ordinary information records, title/run boundaries, final totals, warnings,
  errors and crash context retain reliable delivery. A delivery policy selects
  reliable totals from the same report functions.
- The existing logger worker aggregates omitted optional records into a warning,
  limited to one every five seconds during ordinary operation. Explicit flush and
  shutdown also attempt to report outstanding omissions. No extra worker, timer,
  bundle, or duplicate writer is introduced.
- Explicit optional delivery remains queued even with instant-debug logging enabled;
  reliable records keep existing instant-debug behavior.
- Queued and synchronous sink writes are serialized. On Linux, a fatal signal
  interrupting sink access terminates directly instead of waiting for a helper
  needing the same lock; a custom text backtrace is unavailable on that narrow
  path. Libretro reports omissions through its active callback.

The previous release already corrected nonblocking flush insertion, staged large
incident copies off startup, guarded zero-stride Combo input, and contained terminal
shader failures. Those changes are retained. This follow-up changes logging delivery
only; it does not alter shader selection, rasterization or draw order.

## Interpretation and limits

<!-- CodexAstraUlt: Pressure-related omissions must not be mistaken for complete measurements. -->

An omission warning means optional progress snapshots were not recorded. Do not
treat that interval as complete performance evidence. Final totals remain reliable,
but abrupt termination can still prevent their delivery. Not all logging becomes
nonblocking: essential records retain waiting delivery, and synchronous debug
logging still has overhead. This does not diagnose or fix Dark Moon's observed
graphics/performance failure.

File-only optional Android crash recovery remains bounded and tolerant of missing
services. Normal export remains current/previous/older. No new permission, service,
telemetry, in-app crash browser or runtime dependency is introduced.
