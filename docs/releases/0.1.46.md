# Uberhar 0.1.46 — less repeated rendering work

<!-- CodexAstraLocal: Explain delivered mechanisms separately from pending release gates and owner hardware acceptance. -->
This candidate reduces repeated CPU preparation in Native/Combo and CPU Software,
and simplifies Calculated's compute failure path to address a suspected driver
compilation regression. Hardware gains and experimental gameplay remain unverified.
The owner performs all hardware tests; the development session stops after gated
build submission. A submitted workflow is not a published or installed APK.

<!-- CodexAstraLocal: Preserve beneficial workload placement rather than interpreting greater CPU occupancy as greater speed. -->
Native/Combo decodes fragment registers once per preparation call. Generic
fragment controls are expanded only when a generic/static shader or possible
command-worker fallback needs them. An already-ready full CPU-layout fragment
does not pay for that expansion. Exact original configuration and complete device
profile equality allow reuse of the pure prepared bytes. Pipeline readiness,
execution identity, descriptors, draw order and queued state ownership stay live.
No shader cache on disk is required for this reuse within a run.

CPU Vertices remains an independent Combo option, default OFF. Owner Sonic
observations show that forcing CPU vertices can substantially hurt performance;
Dark Moon's earlier pacing observations are not a universal placement policy.
Existing GPU vertex eligibility, CPU worker limits, prefix overlap and parallel
texture thresholds are preserved. This release adds no GPU offload and no draw
skipping. The existing controls remain available for owner comparisons.

<!-- CodexAstraLocal: State CPU Software's exact removed work without claiming a repair to the unresolved demanded-coordinate producer. -->
CPU Software prepares six-stage combiner state and depth constants once per
triangle, then shares those immutable values with the existing joined workers.
It resolves only operands consumed by each combiner operation and skips primary
color interpolation or lighting when no executed stage consumes those values.
Lighting reuses identical view/half-vector normalizations. Stage order, buffer
updates, quantization and demanded texture accesses retain their existing rules.
Fire Emblem's captured NaN texture-coordinate producer is not claimed fixed;
there is no clamp, dropped draw or Native substitution.

<!-- CodexAstraLocal: The compiler-complexity change is a concrete candidate fix, not a proven explanation of ErrorUnknown. -->
Calculated moves reconstruction of original clipping-failure operands from
nested failure branches into one terminal epilogue and passes only needed
position/scalar operands through those branches. Successful clipping arithmetic
and the failure record remain unchanged. This targets the increased kernel
complexity introduced in .45; the exact Thor pipeline-rejection cause remains
unconfirmed.

Compute shader-module/pipeline Vulkan errors now use the existing typed rendering
stop instead of escaping through generated guest execution. The first failing
compute owner can retain bounded source/SPIR-V/context files locally in the log
directory. No automatic upload, successful-draw file I/O, retry or Native fallback
is added. Temporary diagnostic sections carry `CodexAstraLocal TEST-ONLY LOG`
markers and removal conditions.

<!-- CodexAstraLocal: Keep automated checks and target functionality distinct. -->
The consistent native compile, focused route/Software/compute checks and independent
source/purpose review are complete. The existing shader/Android/signing/publication
workflow must still pass before the candidate is available. Local checks are not
Android or driver qualification. The retained Calculated midpoint-color difference
from .45 remains unresolved.
Neither a graceful rendering stop nor host test success qualifies Software or
Calculated as playable. Actual Dark Moon/Sonic performance and experimental
scene progress require owner testing after publication.
