## Direct fixes

- Resource-pool searches now use refreshed GPU completion. The inherited copied
  value could retain another allocation batch instead of reusing completed slots.
- Stream-buffer creation frees successfully allocated Vulkan memory when later
  bind/map work fails. Constructor cleanup also covers exceptions during initial
  watch-vector allocation and other partial construction. Buffer destruction
  precedes memory release; existing retry sizes and in-flight reuse rules remain.

Host regressions reproduce both defects and fail on the old source. Neither defect
is yet established as Dark Moon's sustained memory-loss or graphical-fault cause.

## A controlled diagnostic route

Choose **Combo (generic fragments)** in the existing graphics-profile controls.
It is persisted as mode 4; existing modes retain IDs 0–3. It keeps Combo's GPU
vertex admission, CPU fallback and measured rectangle-compute behavior, while
disabling optional fragment specialization. Unsupported generic states still use
mandatory accurate recovery. It does not add a second draw or skip a pending draw.

Compare Native, this new mode, and full Combo at the same 2x opening scene. GPU
promotion counts can differ because generic Combo removes the optional fragment
readiness dependency; consult selected/deferred counts when interpreting speed.
This is an explicit diagnostic choice, not a hidden Dark Moon override or a claim
that generic fragments are faster. A fragment-only optimization is deliberately
deferred until resource ownership and correctness are established.

## Bounded memory evidence

Android's existing 30-second health sample now records PID, process RSS/high-water,
anonymous/file/shared RSS, swap and JVM heap alongside native heap and system
availability. A read is capped at 16 KiB plus one overflow sentinel. Missing data
remains unknown. Existing run-start/native-return hooks add two process snapshots
for comparing title lifetimes, before the normal final log flush.

Vulkan samples report VMA explicit allocation/block bytes, raw stream bytes and
allocation-event peaks, descriptor/command capacities, cached completion ticks,
mode, configured resolution, process/run and allocator generation. Periodic
snapshots are at most once per 30 seconds, checked every 64 completed frames;
stalled rendering can delay them. Existing cache-clear and teardown boundaries
provide reliable before/after snapshots. No new worker, GPU wait, bundle,
permission, continuous memory scan or duplicate writer is added.

These counters have different scopes and must not be summed with RSS. VMA block
peaks are sampled, raw-stream peaks are allocation-event based, and pool capacities
are object counts rather than driver bytes. VMA usage/budget heuristics are not
reported. Opaque driver/compiler/pipeline ownership remains unknown. Reserved empty
VMA blocks can survive until allocator destruction; live allocations should not.
