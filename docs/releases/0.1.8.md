# Uberhar 0.1.8 — ready GPU vertices in Combo, bounded index rescue

<!-- AstraPro: Owner-authorized development update, retaining Native as the control. -->

## What changes

- Native and Compute: retry conservatively rejected fused-input batches using a
  validated scan of actual indices, not the entire 8/16-bit domain. Scan only on
  range rejection, cap at 262144 indices, and retain legacy loading for malformed
  ranges or live indices outside the new bound. No vertex values, defaults, FIFO,
  shader arithmetic or ordering changes.
- Automatic/Combo: opt-in ready-only GPU vertex processing through inherited
  Azahar VS/fixed-GS translation, while retaining existing generic/specialized
  fragments. Only complete no-guest-GS lists with an empty assembler, no debugger,
  96..65535 indices and at most 4 MiB speculative uploads are eligible. Native and
  ordinary Compute retain CPU vertices.
- Completed successful pipelines require exact execution-state and host-module
  matching, not only a hash. Pending/failed/capped/unsupported candidates execute
  the full CPU draw. A rejected speculative preparation cannot invalidate the
  framebuffer owner. Drain shared users on cache reload/title switch/shutdown.
- Bound optional caches at 128 VS, 128 GS configs and 256 GPU pipelines; allow one
  optional VS compilation and one serial GPU pipeline build at a time.
- Add bounded index-rescue, accepted GPU-route, topology and shader-admission
  diagnostics. Health snapshots retain the 30-second IO-worker cap, add fixed
  read-only CPU current/max frequencies, separate elapsed/uptime, and mark zero
  heap readings unknown. No power, fan, clock, permission or driver-workaround
  changes. Host Performance-mode switches remain unobserved.
- New source and explanatory notes use AstraPro; retain AstraEH/upstream credit.

## Why

Seven 0.1.7 sessions show 68.643% of Kid Icarus no-GS invocations falling back to
legacy input, but Dark Moon already has 99.906% fused coverage while accumulating
306.829 s inside the CPU vertex stage (~81.248% of observed wall time). MH4U also
exposes 72.523% specialized fragment recovery, predominantly Shadow2D/AddSigned.
The owner reports heat and host Performance-mode changes; the log cannot prove
thermal throttling or locate those switches. These conditions prevent clean
version-speed attribution. See ../UBERHAR_LOG_ANALYSIS_0.1.7.md for all sessions.

## Validation and limitations

Complete host suite passes; new checks include 4099 index/rescue differentials,
36864 bitwise input comparisons, 704 admission cases, 200000 ordered routing
choices and production framebuffer cancellation/retry. New test paths pass
ASan/UBSan. Six integration C++ units pass syntax; pure Kotlin health helper
smoke passes. Vulkan fragment validation passes 1066 modules per optimizer mode.
Full pixel execution status is recorded separately at handoff. Actions retains
all shader/pixel/Vulkan, Android/unit-test, package/signing and publication gates.
No 0.1.8 Thor speedup, pixel parity, or APK availability is asserted here.

The new route is not a full compute renderer or an automatic fastest-path model.
Foreground VS translation, speculative uploads, compiler contention and existing
CPU first-use waits can still stall. GPU precision/coverage needs device testing.
No Shadow2D/AddSigned/gas support guard is removed; high-resolution ghosting,
physical latency and universal 400%/200% headroom are not fixed or certified.
The routine development signing arrangement and all existing package checks are
unchanged. 0.1.8 remains an experimental prerelease, not a 0.2 promotion.
