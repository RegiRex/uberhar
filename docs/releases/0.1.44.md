# Uberhar 0.1.44 — CPU work overlap and experimental renderer recovery

<!-- CodexAstraLocal: Release the accepted performance and startup corrections together; hardware acceptance remains a separate measurement. -->
Native can now prepare full specialized fragment shaders for its existing CPU
vertex layout. Cold draws retain the complete generic path until specialization
is ready. This moves repeated generic shader decisions into bounded CPU
preparation without adding draw skips or waits for optional work.

<!-- CodexAstraLocal: Describe the exact concurrency boundary and placement control rather than promising a CPU occupancy or frame-rate result. -->
Eligible parallel CPU vertex batches can assemble a completed prefix while other
CPU workers finish later shader grains. Results remain ordered; unpublished
assembly is reversible on failure, and all workers join before GPU submission.
Small jobs and sinks without reversible output retain their existing execution.
The Graphics settings add **Use CPU vertices in Combo**, initially off. It keeps
guest vertex calculations on the CPU in either Combo preset without changing
fragment policy. Restart the game after changing this comparison control.

<!-- CodexAstraLocal: Connect the Software correction to observed failures without replacing consumed invalid data with invented output. -->
CPU Software samples only textures actually consumed by the active texture
combiner, lighting or shadow operation. Fixed-LOD sampling avoids unused
derivatives. Finite out-of-range shadow coordinates follow border/edge rules.
Invalid consumed values still stop with a bounded diagnostic. Rendering errors
raised inside a guest CPU service return out of generated code before reaching
the existing error handler, preventing an exception from crossing JIT frames.

<!-- CodexAstraLocal: Fix the demonstrated 64-set/16-set capacity mismatch and bound failure; do not claim all remaining Calculated domains are supported. -->
Calculated's descriptor pools now accommodate their actual allocation batch and
per-type descriptor counts. Exhaustion tries retained pools and at most one fresh
pool; other failures terminate promptly. Failed growth preserves live resource
ownership. The Vulkan worker also catches next-command-buffer allocation errors
through its existing terminal-error path. Calculated remains independent Vulkan
compute, with no Native fallback and explicit errors for unsupported states.

<!-- CodexAstraLocal: Distinguish finite source checks from pending device results and beta acceptance. -->
The integrated native build and focused CPU ordering, fragment selection,
Software sampling, JIT recovery and allocation checks pass. See the
[architecture and cleanliness review](../UBERHAR_REVIEW_0.1.44.md).
Android compilation, shader validation, signing and publication remain mandatory
release gates. Thor testing must establish startup, output and sustained speed;
this candidate does not yet establish 99% Dark Moon speed or three useful CPU
core-equivalents. The long-term target remains correct, smooth first-run gameplay
without saved shader caches, progressing from 2x toward 4x.
