# Uberhar 0.0.6

Android ARM64 experimental alpha for Ayn Thor. After the build and publication
gates pass, install **uberhar-0.0.6-arm64.apk** over Uberhar. The log picker,
application identity and signing-certificate continuity checks are retained.

## Why this update

The complete 0.0.5 Awakening log records **29.128 seconds of scheduler pipeline
waits cold**, and **3.943 seconds warm** with different gameplay. In the cold run,
51 fallback pipelines spent 24.113 seconds inside driver creation calls yet
served only 149 draws. Vertex/geometry dependencies were a small part of fallback
build time. These overlapping worker times must not be added to scheduler waits.
The previous 0.0.3 cold capture recorded 18.222 seconds of waits; differing runs
prevent a controlled comparison, but the evidence does not establish a 0.0.5 win.

## Changes

- **One compact TEV interpreter loop instead of six expanded copies.** It still
  executes six stages in order, including stage-0 Previous redirection, rounding,
  scales, DOT3 alpha and delayed buffer writes. A core SPIR-V DontUnroll hint asks
  the driver to preserve the loop. No new Vulkan device extension is required.
- **Reuse texture results within each fragment's TEV evaluation.** Referenced
  texture units are sampled once, and unused operands are skipped. Lighting
  sampling remains separate. Unused texture units are not fetched eagerly.
- **Restore normal driver optimization.** Remove 0.0.5's DISABLE_OPTIMIZATION
  experiment. It did not demonstrate a latency benefit in the supplied captures;
  the compact shader now addresses code size directly. Device timings are needed
  to assess the combined change, not attribute gains to an individual part.
- **Measure fallback usefulness and size.** The log adds completed used/unused
  fallback pipeline counts, driver-call time spent on currently unused fallbacks,
  and GLSL/SPIR-V byte sizes in bounded build records. `diagnostics=3`,
  `compact_tev=true` and `path=fallback_compact` identify this implementation.

The representative unlit fragment family in the host probe shrank from 73,980
to 24,892 SPIR-V bytes with frontend optimization disabled. This is compiler
input size, not a measured Qualcomm compile-time or frame-rate improvement.

First-ready scheduling, the one-in-flight fallback admission limit, cache caps
and unsupported-state exclusions remain. No draws are skipped in hybrid mode.
First-use pipeline stalls remain possible: this is still a partial fragment
fallback, not a complete precompiled PICA renderer or a zero-stutter guarantee.

## Validation and limits

Before push, the production generator passed **57,344 exact RGBA8 comparisons**
against specialized GLSL across 224 programs on Mesa llvmpipe. Another 57,344
checks verified exactly one fetch per referenced TEV texture unit, including
directed repeated-reference and unused-operand cases. These use synthetic texture
colors and do not verify real texture derivatives or Adreno rendering.

All **128 full Vulkan module checks** passed: 64 families with each frontend
optimizer setting, SPIR-V validation, and preservation of the loop hint. Existing
completion tests and eight manifest regression tests also passed locally. Android
compilation, APK/package/signature validation and the repeat shader gate must
pass in GitHub Actions before publication. Runtime correctness and performance
still require a Thor test. There are no new Android permissions or dependencies.

## Retest

1. Keep the same Qualcomm driver and **2x resolution** for comparison with the
   supplied log. Set **Hybrid TEV on**, **Force TEV fallback off**, and restart
   the game. Keep the other settings unchanged.
2. Exit to the game library, long-press Awakening, then
   **Delete Shader Cache → Vulkan → OK**. Clear it only before the first run.
3. Play a repeatable section at normal speed, then exit through the emulator menu.
4. Replay the same section with the cache retained and the same speed/settings.
5. Save the **Current session** log and note pauses or visible rendering changes.

The 2x setting controls this comparison; it is not an established requirement
for normal hybrid mode. Afterwards, test 4x and fast forward separately with
Force TEV still off. Forced mode deliberately stays on the interpreter and is
for correctness comparisons, so its sustained performance is not the normal
hybrid performance target. Changing gameplay can reach new shader states without
creating a separate fast-forward cache.

Reading a ROM cannot reliably enumerate every host pipeline: fragment behavior
is assembled from live PICA registers and combined with vertex programs and
fixed-function pipeline state. Azahar already reloads observed shader/pipeline
records at startup. Future work should broaden reusable fallback coverage and
prewarm useful observed fallback states, while measuring the extra work; simply
renaming existing cache loading as preprocessing does not solve cold misses.

See the [0.0.5 log analysis](../UBERHAR_LOG_ANALYSIS_0.0.5.md) and the
[Khronos control-flow attribute specification](https://github.khronos.org/Vulkan-Site/glslext/latest/glslext/ext/GL_EXT_control_flow_attributes.html).
