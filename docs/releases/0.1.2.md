# Uberhar 0.1.2 — loading context and less fragment work

<!-- AstraEH: Improve general Native rendering and make loading attribution reviewable. -->

## Changes

- Prepare the generic texture-combiner (TEV) stage activity and loop end once per
  draw. Fragments skip repeated passthrough decoding and trailing passthrough
  stages. Intermediate delayed combiner-buffer updates remain ordered. This
  targets sustained graphics cost without multiplying shader families.
- Record known frontend cache-loading time separately. Add guest-read/submission
  evidence for possible in-game loading, with explicit uncertainty. Quiet gameplay
  and compilation waits alone do not count as loading.
- Add the optional in-game **Test phase** chooser: Automatic, Loading or Gameplay.
  It annotates the current run without changing emulation. Use Loading while
  waiting, then Gameplay when interaction resumes. New launches reset to Automatic.
- Attach phase context to generic compilation waits, bounded build details and
  retained frame hitches. Keep Unknown/Mixed time visible and retain whole-run
  totals. New stage-plan histograms show which draws benefit from the optimization.

These diagnostics do not automatically recognize every game's loading screen or
move unknown shaders into it. In-game prewarming needs validated pipeline
recipes and a budget; uncertain phase hints do not authorize speculative work.
No draw is skipped to hide compilation. Existing specialized recovery and driver
workarounds are retained. No additional Android permissions or network logging.

## Validation

Local validation passed:

- 188,416 exact RGBA8 comparisons and texture-use checks across 736 TEV programs,
  including all 64 active-stage masks, both scale-one encodings and delayed
  buffer updates.
- 1,081,344 exact color comparisons and the same number of depth/discard checks
  across 1,056 full fragment states.
- 1,066 Vulkan modules validated both before and after optimization; the loop
  control and 128-byte ABI checks passed.
- Host correctness suite, core/renderer syntax checks and eight manifest tests.
  Phase tests also passed under address/undefined-behavior sanitizers: startup
  override, transitions, reset, pauses, concurrent reads, ambiguous streaming
  and independent retention of gameplay hitches.

Android compilation and publication gates remain pending. No APK is described
as ready until those gates pass. Thor performance remains untested until device
runs; host correctness is not a device speedup measurement.
