# Uberhar 0.0.8

Experimental Android ARM64 alpha for Ayn Thor. Install **uberhar-0.0.8-arm64.apk**
over Uberhar once this pre-release appears with its APK. GitHub Actions must pass
the Android, shader, package and signing gates before publishing it.

## Why this is a larger update

The supplied 0.0.7 Awakening log records **18.957 seconds** of cold scheduler
pipeline waits versus **18.849 seconds** in 0.0.6; both warm runs record zero.
Fallback fragment families fell from 37 to 18, but driver work stayed near
10.075 seconds. Workloads differ, so this is not a controlled benchmark, but it
does not establish a latency improvement. The
[device analysis](../UBERHAR_LOG_ANALYSIS_0.0.7.md) explains the next steps.

## Renderer changes

- **Broader fragment interpreter.** Alpha comparison, scissor mode, W/Z depth
  mapping, fog and fog direction, emulated border axes, texture-coordinate
  selection, and ordinary/projected/disabled 2D texture modes now travel as
  per-draw data. Compatible draws share a fragment module without compiling
  every combination. The private push-constant ABI grows from 100 to 108 bytes;
  offsets are asserted in C++ and checked in compiled Vulkan SPIR-V.
- **Ready CPU vertex bridge.** While an accurate GPU specialization compiles,
  eligible draws can use the existing CPU vertex engine and a completed generic
  pipeline with a fixed vertex interface. This removes the guest vertex program
  and layout from that fallback pipeline's identity. The renderer makes the
  decision before recording a draw, verifies the complete execution key again
  before binding, and returns to GPU specialization when it is ready. Admission
  is initially limited to complete triangle-list batches of at most 4,096
  vertices. Strip/fan batches retain the established path.
- **Reuse equivalent host pipelines.** Guest configurations that already share
  actual host shader objects can reuse a complete pipeline. Unused vertex-layout
  tails and inactive blend/depth/stencil fields no longer generate redundant
  runtime keys. Active state remains distinct. Transferable disk records still
  store guest shader IDs; process-local identities are never written to them.
- **Fallback failure recovery.** An experimental frontend/module/pipeline failure
  completes its handle as failed, wakes waiters, and selects the accurate
  specialized path. Failed handles cannot win first-ready selection, including
  forced comparison mode. Failure messages are capped and counted.
- **Feature-specific diagnostics.** CPU preparation, execution-cache reuse,
  foreground VS translation, actual scheduler waits and worker driver time are
  reported separately. Capability probes gather evidence for future graphics
  pipeline library work without enabling extensions or bypassing workarounds.
  Every Uberhar renderer log call is marked **`AstraEH Log Line`**. Details are
  capped; aggregate reports occur at most once per five seconds plus shutdown.
  See the [diagnostics map](../UBERHAR_DIAGNOSTICS.md).

**CPU vertex bridge (experimental)** is a new independent Graphics switch,
default on, effective only with **Hybrid TEV on** and **Force TEV fallback off**.
Restart the game after changing it. Hybrid itself remains off by default.
Turning the bridge off isolates the new fragment/pipeline improvements from CPU
vertex routing. Host-pipeline identity improvements also apply with hybrid off.

## Validation and limits

Local production-code checks pass:

- 6,160 family/source/idempotence checks: 3,032 pairs merge and 48 stay distinct.
- 128 full Vulkan module validations, both frontend optimizer modes, with
  DontUnroll and the 108-byte state offsets verified.
- 57,344 exact RGBA8 combiner comparisons and 57,344 texture-fetch checks.
- 192 complete fragment-state cases: **196,608 exact RGBA8 pixels** and the
  corresponding **196,608 depth/discard comparisons**, including real patterned
  textures, projection, alpha, fog, scissor, border and lighting cases on Mesa.
- 36 production pipeline-key checks, CPU bridge eligibility and failure-aware
  normal/forced selection tests, and completion tests including 1,000
  publication races.
- Native syntax checks for all five changed Vulkan implementation files,
  162 Android setting-key declarations and eight manifest regression tests.

These are host checks, not Thor performance measurements or a whole-game
CPU/GPU vertex equivalence test. The full fragment test adapts Vulkan resource
declarations for an OpenGL offscreen context. It does not validate Adreno driver
behavior. CI repeats the shader/policy/package gates and builds the actual APK.

The generic bank still warms **on demand**. Its first native pipeline state may
stall. CPU vertex execution can cost time and can invoke the existing CPU JIT
on a new program. This is not a compilation-free GPU vertex interpreter, full
startup bank, or promise of zero pauses. The bigger generic fragment shader can
also cost more GPU time; ready specializations retain priority in normal mode.

Lighting/procedural shader structure and typed cube resources still create
families. Native blending, attachments and other active fixed state still need
compatible pipelines. Shadow paths, custom normal maps, gas fog and AddSigned
combiners use specialization; AddSigned remains excluded after earlier rounding
differences. Native draw ordering and the hybrid no-skipped-draw policy remain.
The normal one-in-flight fallback build limit and cache caps remain in force.

No Android permissions, external runtime dependencies or new Vulkan extensions
are required. Application identity, log export, manifest validation and signing
continuity gates are retained. Existing source fingerprints can regenerate
cached frontend programs after updating; disk record layouts are unchanged.
Display synchronization and model clarity remain later roadmap items.

## Test when ready

1. Keep the same Vulkan driver, **2x resolution**, **Hybrid TEV on**, **CPU vertex
   bridge on**, **Force TEV fallback off**, and other settings unchanged.
2. Exit to the game library. Long-press Awakening, choose **Delete Shader Cache →
   Vulkan → OK**. Clear only before the cold run.
3. Play the same section at normal speed, exit through the emulator menu, then
   repeat with the cache retained. Save the Current session log after both runs.
4. Report pauses and any missing geometry, lighting/texture differences or crash.
   If the result worsens, a separate cold/warm pair with **only CPU vertex bridge
   off** will isolate its effect. Restart after toggling it.

Keep 4x resolution and fast forward for a separate comparison. The next full
architecture review remains due around 0.0.10, within the agreed 3–5-build cadence.
