# Uberhar 0.0.15 — compact runtime lighting

<!-- AstraEH: Reduce repeated lighting compiler input and prepare throughput testing. -->

0.0.14 retained near-full warm speed and reduced shader families, but its larger
individual programs raised cold generic waiting from 2.948 to 3.298 seconds in
the supplied Thor tests. This alpha targets that cost with **one ordered runtime
lighting loop**, instead of repeating its code for each enabled light.

- Carry light count and per-slot directional, two-sided, attenuation, geometry and
  shadow flags as draw-uniform state. Variations can share one compact program.
- Process only active slots in their original order, retaining physical source
  remapping/duplicates, inherited LUT indexing, disabled LUT defaults and final-slot
  Fresnel. Global bump/shadow structure and cube/2D resources remain specialized.
- Use the guaranteed 128-byte push-constant minimum (ABI 5). Existing draw ordering,
  failure recovery, driver workarounds and CPU vertex processing remain intact.
- Compare current families with 0.0.14/0.0.13/0.0.12 keys for the same observed
  workload. Add bounded runtime light-count coverage and update family details.
- Add fixed normal/fast/uncapped frame totals for the upcoming 400%-cap tests.
  Record achieved speed separately from the cap. Explicit sleep remains excluded;
  limit-transition intervals remain in overall totals but are omitted from band
  attribution. At most three additional lines are emitted on normal shutdown.

All new sections use AstraEH attribution; new diagnostic calls carry searchable
`AstraEH Log Line` markers. Renderer diagnostics 12, frame schema 2 and ABI 5 identify
this build's formats. See the [device analysis](../UBERHAR_LOG_ANALYSIS_0.0.14.md)
and [diagnostic definitions](../UBERHAR_DIAGNOSTICS.md).

## Test on Thor

Keep **Native at 2x**. Clear Vulkan cache once, then run the usual section cold and
repeat warm without clearing, using **emulator fast-forward capped at 400%** in both.
The achieved speed may be lower; that is useful evidence. In-game fast-forward
alone does not request faster emulation. If practical, leave a short battle portion
at 100% to check normal-speed pacing too; the new summaries separate the samples.

Exit normally and export the combined log. Note visual differences, battle slowdowns,
unusually long pauses, new ally attacks and any interruption. Pause or close the
system when stepping away; the prior log confirms its sleep pause was excluded.
Do not raise resolution in the same comparison. Once the 2x result is stable, test
3x and 4x separately. No driver download or additional graphics switches are needed.

## Scope and beta milestone

A compact loop adds uniform control flow and dynamic indexing. Smaller compiler
input and fewer keys do not prove faster GPU execution; Thor testing must show
both improved cold latency and preserved warm speed/images. First-use native
pipelines and unsupported-state recovery still compile. Compute coverage, display
synchronization and general GPU vertex interpretation are not expanded here.

Keep this version 0.0.15. Move to 0.1.0 after repeatably satisfactory cold/warm Native
runs, retained image quality and stability, no skipped draws/experimental failures,
and a useful fast-forward assessment. Reaching the 400% cap or 4x is not a prerequisite;
those are separate performance goals. Beta scope will reflect tested games/devices,
not a universal zero-lag claim. The next full architectural review is still due
by default after 0.0.16 (allowed 0.0.15–0.0.17).

No Android permissions, dependencies, package identity, signing policy or external
services change. APK publication requires all existing build, shader, package and
signature gates. The development turn hands off CI without polling the APK build.

## Local validation

11,472 family/source/idempotence checks pass, including 4,660 merged pairs and
52 retained structural distinctions. Mesa llvmpipe matches **1,081,344 exact RGBA8
pixels** and as many depth/discard comparisons across **1,056 full fragment cases**.
The existing 57,344 TEV color and 57,344 texture-use checks pass.

All **1,066 distinct full Vulkan programs** compile and pass SPIR-V validation with
optimization off and on (2,132 validations), including both no-unroll hints in lit
generic shaders and all nine push-constant offsets. Maximum unoptimized corpus
module size is 54,300 bytes, versus 106,580 in 0.0.14; this is compiler-input evidence,
not a measured Thor speedup. Optimized sizes span 320–79,192 bytes.

Host production probes, integration syntax, speed-band/pause tests, all 163 Android
setting keys, eight manifest-policy checks and formatting/whitespace checks pass.
These are host results. Android compilation and final APK/signature validation run
in Actions, which repeats the shader gates. Thor performance remains pending.
