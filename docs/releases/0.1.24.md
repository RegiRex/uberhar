# Uberhar 0.1.24 — contain unwritten GPU output components

<!-- CodexAstraLocal: Finish the recovered output-default experiment with a narrow proven fallback, preserving historical authorship and separating host correctness from title qualification. -->

The CPU initializes a draw's shader registers to zero and retains their values
within that draw. The optional GPU path initializes each invocation's output W
to one. A mapped output component that no instruction writes can therefore
produce different values. The new Combo admission guard keeps that complete
draw on the CPU before GPU uploads or index reads when it proves this particular
missing-W-write case. Existing CPU execution, invocation order and FIFO reuse
remain intact; no draw is skipped and GPU defaults are not globally rewritten.

The guard composes packed output registers with the final semantic mapping,
including aliases. It scans a conservative union of possible instruction writes
and memoizes exact immutable program/swizzle words in at most 128 entries
(approximately 4 MiB plus bookkeeping). Unknown words prevent the absence proof;
unreachable/conditional writes may prevent rejection. A successful admission
does not prove general register-persistence parity. Transported semantics may be
unused by a fragment, so some safe CPU fallbacks can have a performance cost
without changing visible pixels. Native, Custom and shader generation are unchanged.

## Evidence and limits

<!-- CodexAstraLocal: Keep the two visual symptoms independent and require cold first-run device evidence before assigning the synthetic defect to Dark Moon. -->

The existing 0.1.23 mode-4 experiment retains moon flashing across consecutive
frames with zero optional fragment requests and zero computed rectangles. Its
ghost footage lacks a matched view of the earlier book-holder defect. Neither
symptom is established as the output-W mismatch, and this release is not a
claimed graphics cure, memory bound or throughput improvement.

Focused regressions exercise the production CPU interpreter, output conversion,
generated GPU shader and extracted admission path. They reproduce CPU zero versus
GPU one, retain fully written positive controls, and fail the old unguarded
admission. Independent review found no blocking correctness issue. The required
host/shader, Android, package, checksum, signing and publication gates remain
separate; consult the [progress tracker](../UBERHAR_PROGRESS.md) for their actual
status and subsequent device results.

## Diagnostics and release policy

<!-- CodexAstraLocal: Bound coverage evidence and implement the owner's version classification without weakening release gates or adding a logging service. -->

The ordinary log adds at most eight `Uberhar GPU output fallback` detail records
per renderer lifetime and one teardown total. Records contain masks, hashes,
coverage and bounded memo counts, not guest program payloads. No worker, capture
stream, per-launch bundle or extra GPU wait is added.

The existing gated workflow now marks a nonzero alpha component as a prerelease
and a zero alpha component as a full release, matching Full Release.Beta.Alpha
numbering. Draft upload ordering, exact source provenance, checksums, certificate
pinning and Android/shader gates remain. Version 0.1.24 is an alpha prerelease;
the [0.2 gate](../UBERHAR_ARCHITECTURE_0.1.6.md) is still unqualified.
