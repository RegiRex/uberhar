# Uberhar 0.1.30 — ready optimized fragments for CPU vertex draws

<!-- CodexAstraLocal: Explain the candidate's complete-draw behavior and bounded admission without promising an unmeasured device gain. -->

Full Combo can now select an already-ready optimized fragment pipeline for a
draw whose vertices were generated on the CPU. Previously those covered draws
always used the generic fragment program. The new route keeps the existing
88-byte software vertex layout, trivial vertex shader, CPU execution, register
carry, FIFO, primitive assembly and quaternion handling. It prepares the complete
generic draw first; missing, pending, failed or capped optional work uses that
draw without waiting or skipping it.

A separate CPU pipeline bank admits at most eight entries within the existing
256 combined optional-pipeline ceiling. Fragment shaders retain their shared
128-entry limit, and CPU/GPU pipelines share the existing single pending optional
pipeline allowance. Ready entries remain selectable at the limits; CPU-bank
misses at capacity do not demand new shaders. Exact execution, vertex layout, attachment, profile
and shader-owner keys prevent selecting an incompatible pipeline. Barycentric
profiles remain excluded. Normal shutdown drains the new bank before its owners.

<!-- CodexAstraLocal: Separate failure containment and route observations from proof that a particular workload benefits. -->

The optional fragment worker now contains standard and unknown exceptions,
including failures in its diagnostic logger. Queue-admission failures publish a
terminal failed entry rather than leaving it pending. This changes only the
optional job boundary; the general worker implementation is unchanged.

Ordinary counters distinguish generic, recovery, optional GPU and optional CPU
fragment draws. Their sum must equal all fragment draws. CPU lit/unlit selected
draw counts are separate from pipeline-bank occupancy, which includes pending
and failed entries. The settings label records configured policy; counters prove
actual selection. Mode 4 disables both optional GPU and CPU fragments, so its
comparison does not isolate the new CPU route alone.

<!-- CodexAstraLocal: State the exercised production contracts and host boundaries precisely. -->

Host validation passes: fresh configuration, native integration, CTest with the
same five firmware-dependent skips, and the complete host probe. Selection and
binding tests pass 615 checks and six intended failing mutants. The actual
optional worker passes 498 checks and five intended failing mutants, including
allocation/admission failures and throwing error endpoints. Driver/compiler
endpoints in those tests are controlled substitutes.

The CPU vertex/fragment gate uses production vertex construction, assembly,
software layout and the trivial vertex shader. It passes 32 transform-feedback
controls and 4,224 paired synthetic image/depth cases across 1,056 states and four
geometry/clip variants, plus four contiguous generic/specialized/generic
sequences and nine nonfinite negative controls. Another 128 paired draws execute
optimized OpenGL SPIR-V fragments against generic programs. All 80 generated
modules validate: 40 OpenGL modules execute and 40 Vulkan siblings are validated
but not executed. These are host proofs with adapted bindings and clip state;
they do not establish Adreno performance, Vulkan image parity, epsilon
sanitization or NaN/Inf/subnormal shader inputs. Independent source and test
reviews found no blocker.
