# Uberhar 0.1.27 — bounded CPU vertex attribution

<!-- CodexAstraLocal: Add a focused discriminator after real-device external profiling failed, without presenting measurement work as a rendering or speed fix. -->

Two cold 0.1.26 openings repeated bounded improvements in moon flashing and ghost
corruption, but their complete timing windows averaged approximately 22–23% of
normal speed. A third profiling run showed substantial main-thread CPU work.
Existing broad vertex timers and sparse single-vertex timings cannot determine
which operation accounts for the workload. The Thor's stock external profilers
could not provide usable function or scheduler evidence under its current
release/kernel configuration.

0.1.27 adds an optional finite diagnostic for selected contiguous chunks in
Combo's prepared CPU vertex path. A boundary-only mode records chunk wall and
owner-thread CPU time. Detailed mode additionally measures the actual lookup,
input loading, shader execution, output conversion, cache maintenance and
assembly operations within those chunks. Exact counts and measurement coverage
accompany the intervals; unobserved work is not estimated by expanding a sampled
vertex to the full draw.

<!-- CodexAstraLocal: Preserve the default path and state that an observer's output still requires controlled interpretation. -->

The diagnostic is off by default and requires a bounded title-specific request
plus the existing explicit Gameplay marker. It retains draw order, FIFO behavior
and shader-register carry. It adds no system permission, background sampler,
signal handler, kernel-policy change, GPU query or shader-cache dependency.
Native and Custom remain outside the opt-in diagnostic. At most 64 chunks and
4,096 inputs are measured; a bounded report is retained after normal exit without
overwriting an earlier artifact.

Detailed clocks have overhead. Use matched request-free, boundary-only and
detailed controls, inspect program/entry/count coverage, and retain calibration
without subtracting it as a guaranteed correction. Chunk wall-minus-thread-CPU
is not GPU execution time. This release is a measurement candidate, with no
performance improvement or new graphics cure claimed. See the
[diagnostic protocol](../../tools/uberhar/VERTEX_TIMING.md).

Three cold controls completed normal return: request-free, boundary-only and
detailed. The request-free opening averaged **22.568%** over 40 complete normal
windows. Consecutive review found no earlier flashing in the recorded moon
sequence and no earlier dense irregular corruption in three bounded ghost
sequences; broader correctness and transparency remain unqualified. Both
diagnostic reports passed all 64 chunks, stopped at the record budget about
6.4 seconds into eligibility, and recorded no clock, identity or phase failure.
Detailed clocks materially perturb these small samples; workload attribution and
a matched observer-cost estimate remain open. Same-process GPU memory recovered
to **13.00 / 12.70 / 12.88 MiB** after the respective normal exits. These results
do not qualify sustained speed or long-game memory bounds.
