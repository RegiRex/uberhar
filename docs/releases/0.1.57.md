## Incorporated main 0.1.57 changes

<!-- CodexAstraUlt-2: Retain main's controls and implementation descriptions while distinguishing the comparison's build and device scope. -->

This comparison also incorporates the following main work-reduction mechanisms
and settings. Reusing a fragment configuration never bypasses per-draw pipeline
readiness, CPU transport requirements or current-resource checks. Full recipe
state remains recorded even when the current driver uses dynamic state.

- **Changed-only state preparation:** pure unchanged register writes avoid needless
  dirty-state invalidation; immutable fragment configuration can reuse its prepared
  value. Trigger/port side effects, masked-write ordering, command timing, readiness
  selection and current resources still follow their existing paths.
- **Guarded render-pass containment:** reuse a compatible active framebuffer/pass
  when its original area contains the next requested area. Clear, utility,
  shadow/storage/feedback hazards and required submission boundaries retain their
  separation. Commands remain ordered and LOAD/STORE behavior is unchanged.
- **Typed ordered append:** eligible CPU vertex batches use a concrete primitive
  sink, removing repeated erased callback/virtual dispatch. Triangle/strip/fan
  ordering, winding, quaternion conversion, append rollback and fallback remain.
- **Adaptive history repair:** a fixed table retains separate histories for exact
  recurring work identities/shapes. Unknown or mixed work stays with static
  admission; histories expire/requalify and capacity changes reset comparison.
  Adaptive OFF bypasses cohort bookkeeping while retaining the static worker pools.
- **Include scissor narrowing:** narrow the Vulkan scissor only for the guest's
  Include region, retaining guest shader clipping and pass bounds. Exclude mode is
  not approximated with one rectangle. Reported areas are bounds, not fragment counts.
- **Independent observation:** Detailed GPU pass timing can disable pass query
  allocation/commands/polling/attribution. Functional compute-selector timestamps
  remain policy inputs, and ordinary diagnostics remain. The separate default-OFF
  frame census counts successful enqueues per rasterizer callback, configured
  target/texture state and observed guest transfer lineage. Fixed descriptor
  capacities, metadata quotas, saturation and unconfirmed diagnostic delivery are
  explicit. Callback counts are not guest FPS; configured mips, nominal bytes and
  sparse host report time are not sampled mips, bandwidth or GPU execution time.
- **Narrow driver comparison:** the default-OFF V38 static-state control forces the
  existing static alternative to extended dynamic state when running Turnip. It
  does not change border-color policy or promise a fix for a driver version.
- **Separate eye controls:** displayed-eye-only presentation preparation omits an
  unused mono eye's preparation while retaining valid descriptors and complete
  screenshot/stereo consumers. A separate default-OFF early-right-eye experiment
  also requires the original Disable Right Eye Render request and title policy.
  It targets dedicated right-scanout work with checks for mono selection, matching
  dimensions, shared left targets and visible depth/stencil/geometry/shadow/feedback
  conflicts. Later consumers of already omitted output remain a correctness risk,
  so observed hazards disable further suppression and are reported. This is not a
  general proof that a guest eye is unused, and hardware qualification is pending.

All mechanisms have alpha-only quick Testing controls with launch-owned values.
Changed-state reuse, contained passes, typed append, Include scissor, adaptive
workers, Detailed GPU pass timing and displayed-eye preparation default ON. Frame
census, V38 static state and early-right-eye suppression default OFF. Optimize
generic shaders returns to quick Testing with its existing default OFF; Turnip
pass-end submission remains in Graphics with saved choices honored. ADPF is deferred
because the available timing does not provide a trustworthy CPU-work-duration and
target contract.

The failed Hardware Shader quick experiment is retired. Native/Combo now fix
ordinary hardware shaders OFF; Custom/OpenGL preferences and Combo CPU-OFF's
independent ready-GPU route remain. Linear Filtering is removed only from quick
Testing: ordinary Graphics filtering remains, default ON. Active legacy quick
filtering choices migrate to their matching ordinary scope only where no explicit
ordinary value exists; retired keys are retained as inert metadata. Custom data,
per-game driver access, shared scrolling and live resolution remain intact.

Precedence remains ordinary global → explicit global Testing → ordinary title →
explicit title Testing. Present false/zero values remain overrides. Options edits
global scope, title reset requires confirmation, and beta/full releases hide and
ignore Testing overlays. See [settings details](../UBERHAR_PER_GAME_SETTINGS.md).
