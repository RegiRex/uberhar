# Uberhar 0.1.57 — precompiled-first comparison

Prepare known Vulkan CPU-fragment shaders and pipelines before gameplay, then
select ready full/static specializations before creating or waiting for a generic
shader. Record complete encountered CPU recipes and import compatible stock cache
descriptions without changing Custom cache files. Retain a bounded prioritized
pipeline bank and attempt driver-cache warming for remaining known recipes.

Preserve exact state/profile identity, shared memory admission limits, cancellation,
atomic cache writes and shader/pipeline lifetimes. Startup device loss now latches
terminal cancellation and avoids a repeated wait on the lost device during teardown.
Existing settings and driver selection remain in force.

A cold title with no compatible records still has unknown states. Driver-warmed
work is distinct from resident ready pipelines, so generic fallback can remain
necessary. This does not establish a steady-state speedup or fix Luigi's Mansion:
Dark Moon's earlier rendering/crash reports. See the [architecture and limits](../UBERHAR_PRECOMPILATION.md).

The comparison branch is `uberhar/precompiled-first`, based on 0.1.56-r2. Its distinct
`precompiled-first-comparison` artifact now installs as **Uberhar Precompiled**
(`org.uberhar.uberhar_emu.precompiled`) beside main Uberhar, with approved signing
checks retained. Select a separate empty data folder; main-Uberhar folder markers
are no longer accepted by the comparison. Private settings and files are separate,
and existing main data is not automatically migrated. The same-repository PR route
checks the immutable head;
the candidate branch cannot publish a GitHub release.

New codec/import/preparation/device-loss checks and existing compiler/cache/workflow
checks passed locally, including deliberate-defect controls. Both fragment-generator
translation units and the production TEV-family suite passed. Full Vulkan routing
fixtures are extended but locally blocked by the unavailable pinned oversized
Vulkan header. Hosted shader and Android jobs, then owner testing on the AYN Thor,
remain required. An APK artifact alone is not proof that both hosted gates passed.
