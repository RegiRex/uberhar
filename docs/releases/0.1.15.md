# Uberhar 0.1.15 — restore a readable log picker and repair private logging

<!-- AstraEH: Correct the owner-reported 0.1.14 logging regression before renderer experiments. -->

## Changes

- Remove per-launch session bundles from the main log picker. It now lists only
  current, previous and older text logs with their recorded games and normal names.
- Fix the private journal path: open the physical file directly and hand a duplicated
  descriptor to the native logger. 0.1.14 accidentally interpreted that pathname
  relative to the emulation data folder, causing empty copies and the startup warning.
- Keep a separate **Crash reports** action for actual errors, crashes and unresolved
  interruptions with useful evidence. Ordinary and empty launch bundles are hidden.
  Reports retain available Android exit details and binary traces, even if an older
  build did not populate its private log. An interruption is not automatically a crash.
- Reclaim empty idle launches with no incident evidence. Keep two OS-confirmed clean
  idle backups, preserving crash/error/active/unresolved records until explicit deletion.
- If a genuine logging failure remains, emit one bounded record distinguishing a
  failed queue flush from a failed private writer, in addition to the visible warning.
- Add a regression test using the actual Android file-opening and JNI initialization
  code. Existing retention, export-name, shader, Android and publication gates remain.

No renderer behavior changes. Dark Moon corruption, severe slowdown and crash cause
remain open. Its retained text contains pre-crash activity but no fatal trace. A large
system-memory decline during Dark Moon is a new diagnostic lead, not a confirmed OOM.
Native and Combo performance goals and the per-game settings plan remain unchanged.

## Short device check after publication

1. Update normally; do not clear app data or reinstall. Check whether the logging
   warning appears when opening Uberhar.
2. Play any familiar game briefly and open the log picker. Current/previous/older
   should be easy to find, with no launch-bundle list above them. Export the current
   text log as usual and verify the game appears.
3. Open Crash reports only if useful. It may be empty or contain older incident
   evidence. Export an existing relevant Dark Moon report if present; no new crash
   reproduction is requested. Cancel returns to ordinary log export.

There is no need to replay the benchmark suite or a long failing Dark Moon cutscene
for this logging-only change. Genuine storage failures, unflushed final records,
unavailable OS traces and app-data deletion remain limitations.
