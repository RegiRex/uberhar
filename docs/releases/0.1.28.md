# Uberhar 0.1.28 — grouped CPU output copies and overlay lifecycle

<!-- CodexAstraLocal: Select a bounded shared-path optimization after exact host comparisons, without interpreting perturbed diagnostic samples as workload shares. -->

Cold 0.1.27 Dark Moon openings remain around 22–23% of normal speed. Its finite
diagnostics show substantial owner-thread CPU activity, but do not establish
which function dominates. This candidate reduces scalar output transport where
the final semantic map contains four contiguous components from one register.
It copies their exact bytes together after resolving duplicate destinations;
partial and irregular mappings retain scalar copies. Both live output banks,
register carry, defaults, color conversion, FIFO behavior and draw order remain
covered by production-path differentials. The shared path affects Native and
Combo and therefore requires cold tests in both modes.

Host experiments favor grouped mappings, with smaller regressions in some
scalar-only and constructor cases. Each plan grows by 16 bytes. These x64 results
do not establish ARM64 performance, a representative title benefit or a speedup
on the Thor. Shader arithmetic, GPU admission and shader-cache policy are unchanged.

<!-- CodexAstraLocal: Repair ownership of destructive statistics reads independently of renderer throughput, without claiming the exact cause of a previously invalid displayed rate. -->

The Android performance overlay now owns one callback per resumed fragment view
and cancels it on pause, view destruction and final destruction. Stale callbacks
cannot read/reset shared native statistics or reschedule themselves. This fixes
a source-level lifecycle hazard that can let an earlier title consume a later
title's counters. Native timing formulas and ordinary performance logs remain
unchanged; actual callback counts behind previously implausible displayed rates
were not measured.

Focused output tests pass 998,282 existing bitwise comparisons, 18,432 new
structured grouped comparisons and 384 FIFO/assembly cases; the plan-cache suite

The extracted production Kotlin lifecycle methods pass 34 modeled queue checks;
released 0.1.27 compiles under the same harness and fails 25. Independent source
reviews found no blocker. The full host probe and native core/video/tests/room
build pass. All 67 CTest entries pass or retain their five existing firmware
skips, with zero failures. The existing Android workflow now gates on the Kotlin
regression using a checksum-pinned official compiler; its shell also passes four
host failure-boundary checks. Android, shader, signing, publication and installed
device validation remain pending.
