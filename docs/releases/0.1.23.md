# Uberhar 0.1.23 — optimize optional background shaders

<!-- CodexAstraUlt: Use the owner's new GPU allocation evidence to correct the compilation policy without claiming an unmeasured driver-memory or image cure. -->

The [0.1.22 Dark Moon capture](../UBERHAR_LOG_ANALYSIS_0.1.22.md) identifies
several GiB of growing allocations in Uberhar's own GPU process scope. Combo
reaches 4,232 MiB while Native stays around 1,081–1,093 MiB. Both return almost
all GPU allocations on normal title exit. The growth closely follows retained
GPU pipelines, rather than the already stable explicit buffer/image allocations.
The owner still sees ghost and moon glitches despite a perceived speed improvement.

## Correct the background compilation policy

<!-- CodexAstraUlt: Preserve the generic cold path while removing its inappropriate optimizer setting from optional jobs. -->

The preset disabled frontend SPIR-V optimization to shorten generic first-use
compilation. That setting also reached optional GPU shader jobs, even though
complete CPU draws remain available while those jobs run in the background.

Optional ready-only vertex/geometry shaders and optional specialized fragment
shaders now optimize before they become usable. Required generic/mandatory
compilation and Custom retain their requested compiler settings. Vertex and
geometry workers capture their compiler options before queueing; geometry jobs
also capture clip-plane support. The existing bounded report records
`ready_compiler_policy=optimized_background_v1`.

No new sampler, worker, log bundle, pipeline eviction or draw skipping is added.
The previous input and quaternion correctness guards remain. Existing generic
module identities are unchanged; optional preset shader modules are session-local,
and the driver cache identifies the actual SPIR-V. Manual cache deletion is not
required for the changed optional compilation policy.

This removes a demonstrated compilation-policy inefficiency. Host fixtures show
substantially fewer temporary variables and smaller optimized modules. Whether
that reduces the proprietary driver's large pipeline allocations requires a
Thor measurement. This candidate does not impose a new GPU byte budget, establish
bounded gameplay memory, or claim to repair the remaining ghost/moon artifacts.

Adreno gameplay validation. See [current progress](../UBERHAR_PROGRESS.md) for
