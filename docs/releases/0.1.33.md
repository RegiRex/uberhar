# Uberhar 0.1.33 — isolated Calculated diagnostics

<!-- CodexAstraLocal: The owner requires the next Calculated test to execute no Native/graphics recovery; describe missing output as a diagnostic limitation. -->

Calculated mode disables Native/graphics fallback. Unsupported guest draws are
counted as omitted and do not reach graphics preparation, submission or a retry
through another rendering backend. The existing exact compute admission checks
remain intact. Native, Combo and ComboGeneric keep their complete rendering
policies. The Android label identifies Calculated as an isolated test and warns
that unsupported scenes can be incomplete or blank.

The current calculation kernel supports exact solid rectangles, including the
masked and endpoint replacements introduced in .32. This release does not add
a general 3D compute renderer. CPU vertex processing and presentation remain
shared infrastructure. Missing output and zero useful compute work cannot
establish a rendering speed gain, qualify Dark Moon, or meet the 99% target.

<!-- CodexAstraLocal: Keep broad strict routing evidence separate from the inherited valid-target census and distinguish recorded commands from GPU completion. -->

The rasterizer records computed and omitted strict attempts, including missing
renderer/target cases, with separate empty-batch accounting. The existing
valid-framebuffer raw/effective state census retains its own denominator. An
omitted batch clears its submitted vertices and cancels framebuffer invalidation;
it does not claim newly rendered contents. Coverage logs explicitly identify
recorded commands and whether output is incomplete or compute work is zero.

<!-- CodexAstraLocal: Explain terminal backend refusal and all returned-status consumers, including restore/reset and frontend lifetime cleanup. -->

Isolated Calculated requires a compiled Vulkan backend. Startup rejects other
backend selections before constructing a substitute. Failed renderer restore or
reset terminates the session instead of becoming a recoverable save-file error,
offering continuation with a stopped core, or waiting indefinitely for a frame.
Android cleans already-created frontend resources after a returned startup
failure. Qt applies terminal handling during normal execution and single stepping.
Ordinary save-file errors remain recoverable when the core is still running.

<!-- CodexAstraLocal: Separate the opt-in supported-work comparison from guest routing and game throughput. -->

A default-off Android diagnostic provides one explicitly requested
scratch-target comparison. It uses the production rectangle command sequence and
an independent graphics reference, original hardware vertices, full and partial
channel masks, and complete output checks. Its resources, counters and timestamp
queries do not feed guest coverage or the automatic selector. Unsupported
frontends return before request IO or benchmark construction. The result must
separate setup, host enqueue, GPU commands and readback latency; an incomplete
or mismatched comparison cannot produce an accepted speed ratio.

The merged native build, full host probe and CTest pass, with the same five
firmware-dependent CTest skips. The host probe completes in 485.640 seconds.
The benchmark owner/command checks pass 4,025 assertions and detect nine injected
defects. Its 16 original-input pixel pairs pass, four pixel defects are detected,
and four Vulkan modules validate. The inherited compute gate also passes 256
comparisons, 90 original-vertex pairs, four ordered sequences, eight intended
pixel failures and four validated modules. The Android-only benchmark translation
unit compiles with the pinned NDK for ARM64/API 33.

Host endpoint models and GL pixels do not execute Thor Vulkan. Android release
gates, checksum/signing-compatible installation and target measurements remain
separate requirements. The new benchmark pixel/module step is mandatory in the
existing gated prerelease workflow. No title-performance or graphics qualification
follows from these local checks.
