# Uberhar 0.1.49 — reduce redundant Native/Combo work

<!-- CodexAstraLocal: Describe implemented changes separately from hardware results; CPU occupancy is supporting evidence, not the performance target. -->
This candidate targets Native/Combo CPU preparation and GPU fragment/transfer
costs. It preserves complete draws, guest ordering and independent Calculated
execution. Thor performance and visual acceptance remain unqualified until the
owner tests the published build. No fixed CPU utilization or frame-rate gain is
claimed.

<!-- CodexAstraLocal: Keep arithmetic and resource dependencies explicit in the GPU optimizations. -->
The CPU builds a backward texture-combiner liveness plan from original state.
Generated graphics shaders avoid dead RGB/alpha work and unused lighting/texture
consumers, and alpha-Never exits before unnecessary fragment arithmetic. Eligible
ordinary texture samples shared by lighting and TEV reuse the same immutable
sample. The 128-byte dynamic transport has a new ABI identity; inherited recovery
SPIR-V remains separate and is not claimed to receive every GLSL optimization.
Constant-TEV and directional-light CPU arithmetic substitutions are **not enabled**:
bounded original-input evidence records eligibility and arithmetic limits first.

<!-- CodexAstraLocal: Document exact ownership guards and useful-work grouping rather than promising all cores stay occupied. -->
CPU preparation uses cached negative admission before avoidable setup, a bounded
four-entry semantic mapping cache, and exact reuse of a successful effects-policy
decision. Rejection statistics no longer take a diagnostic-only queue lock. The
asynchronous coordinator starts and reserves its progress lane only when it can
accept real work. Existing permit admission and dependency/retirement rules remain
in force; optional execution-census atomics are disabled in normal production.
Independent small packets can share a cost-qualified ready group without waiting
for it to fill. Per-pool adaptation retains four exact workload histories; unknown
identities do not borrow a different workload's adaptive trial.

<!-- CodexAstraLocal: State the narrow proofs for avoiding GPU work, with no new readback or approximate conversion. -->
Exact same-image copies/blits that change no pixels are removed while preserving
visibility and caller bookkeeping. Feedback snapshots can be reused only while
their source/destination allocations and the recorded-command epoch remain
unchanged. A bounded raw transfer can use CPU copy workers only when both complete
nonoverlapping memory spans are already authoritative in RAM, neither intersects
GPU-dirty data, and concurrent guest writers are excluded. Other transfers retain
the inherited route; the optimization performs no new GPU readback.

<!-- CodexAstraLocal: Correct the inherited pass ownership bug exposed by integration review. -->
Render-pass transitions now close the old pass with its own attachment metadata
before installing the next pass's metadata. This prevents barriers using the new
attachments and prevents the next pass from losing its attachment bookkeeping.

<!-- CodexAstraLocal TEST-ONLY LOG: Remove qualification instrumentation after placement, arithmetic and scheduling choices have been hardware-qualified. -->
Bounded diagnostics record route selections, queue eligibility/group costs,
adaptive-history decisions, CPU copy costs, avoided image commands and owner
waits. A worker-owned timestamp ring samples existing GPU command spans without
waiting for results or splitting render passes. It reports availability, dropped
samples, query errors and polling cost. GPU span durations may overlap and must
not be summed as exclusive frame costs. Logical transfer bytes are not measured
memory bandwidth. Presentation composition is covered; swapchain presentation,
all driver work and every inherited utility command are not fully attributed.

<!-- CodexAstraLocal: Preserve the delivery gates and distinguish modeled/native checks from Android hardware qualification. -->
Validation includes exact shader pixels and Vulkan modules, grouped CPU-work
controls, raw-copy/texture byte comparisons, render-pass ownership controls,
bounded query-lifetime/failure controls and affected native compilation. The
existing Android, shader, signing and publication gates still decide release
availability. Calculated and CPU Software are not the acceptance targets for
this candidate; their outstanding issues are not declared resolved.
