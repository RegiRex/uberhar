# Uberhar 0.1.4 — automatic run settings and cache context

<!-- AstraEH: Reduce manual test reporting while preserving honest cache distinctions. -->

## Changes

- Add readable per-run settings: named mode/API, resolution and Auto status,
  CPU clock/JIT, shader/cache flags, base/turbo limits, presentation options,
  texture controls and render-timing settings, plus exact build and session.
- Report observed setting changes at five-second boundaries or resume, capped
  at 32 details; always retain the final snapshot. These are sampled settings,
  not a guarantee that every option is hot-reloaded by its renderer.
- Inventory the current title's application Vulkan cache before loading:
  generic modules, driver data and specialized records. Mark empty files,
  present files, disabled, incomplete/unknown or not-yet-observed explicitly.
  Scan metadata only, cap directory entries at 8192 and report its duration.
- Report actual generic reuse as cold-encountered, warm-encountered, mixed,
  not-observed or disabled, separately from file presence. Old-build files can
  exist while every newly encountered module still needs compilation.
- Record driver-cache load/failure/fallback status. Provided driver data is not
  proof of internal cache hits; no opaque driver-cache state is invented.

This is a diagnostics and architecture-review release. It changes no shader math,
fragment ABI, rendering order, cache invalidation policy, model profile, speed
limit or phase classification. It neither deletes caches nor prewarms pipelines.
Renderer diagnostics are schema 15; settings/cache records use schema 1. Frame
schema 3 and fragment ABI 7 remain unchanged.

Generic-module fingerprints include the build revision. The first launch after
this update can therefore compile fresh modules even with existing cache files;
the new records make that distinction explicit. Android's native path translation
is honored; unsupported virtual-filesystem inventory stays Unknown.

## Validation

Local host suite, cache-inventory/reuse tests, address/undefined-behavior sanitizer
checks for the inventory, and core/Vulkan integration syntax checks passed.
Tests include absent/zero-byte files, stale data, unrelated titles, errors,
bounded incomplete scans, disabled caching and mixed compatible reuse.

Unchanged shader output still passes through the required Actions pixel/Vulkan
gates. Android build, packaging, signing and prerelease publication are pending
at source handoff. Device overhead and log usefulness need Thor evidence.

## Next test

Use your normal FEA 2x/4x sequence and optional Sonic race. There is no need to
type resolutions or ordinary cache-state labels; the log now captures the relevant
facts. Short notes about partner attacks, interruptions, unexpected visuals or
respawns remain useful. Do not clear caches merely to satisfy a logging test.

Temporary fast-forward and mixed transition intervals are excluded from normal
performance comparisons unless you explicitly request a speed test. Fast-forward
alone does not automatically classify a screen as loading. The existing optional
Test phase control can supply Loading/Gameplay context when convenient.

repeated per-draw bookkeeping next. The next default review is after 0.1.7,
