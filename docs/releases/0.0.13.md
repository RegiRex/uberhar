# Uberhar 0.0.13 — runtime lighting controls

<!-- AstraEH: Cold-cache shader-family reduction after the 0.0.12 Thor milestone. -->

This alpha targets remaining first-encounter fragment compilation. **0.0.12 Native
at 2x remains the measured reference**: 99.760% warm speed, but 8.121 s of cold
generic waiting and occasional long pauses. 0.0.13 needs a fresh Thor comparison;
no device speedup is claimed before testing.

- Supply lighting lookup inputs, signed/unsigned mode, exact scale and physical
  light selection as per-draw data. These variations can share one fragment program
  instead of creating separate compiled families.
- Preserve unrolled light count and lighting operation structure to limit additional
  runtime work. Remapped/duplicate light order, attenuation tables, the inherited
  two-sided LUT indexing and accurate unsupported-state recovery are preserved.
- Extend the private Vulkan push constants to 120 bytes, within the guaranteed
  128-byte minimum. Existing driver workarounds, render order and CPU vertex path remain.
- Log the previous lighting family count alongside the new count for the **same
  workload**, plus remaining lighting/procedural structural counts. Reporting remains
  bounded; new/updated troubleshooting lines retain `AstraEH Log Line` markers.
- Expand shader validation to 416 complete fragment comparisons, including 224
  lighting cases with distinct per-light data and LUT tables. Both Vulkan frontend
  optimizer modes are publication gates alongside the existing ARM64 package and
  signing checks. The shader job receives a longer time limit for this coverage.

The [architecture review](../UBERHAR_ARCHITECTURE_0.0.12.md) is complete after three
alphas. The next default review is after 0.0.16 (allowed 0.0.15–0.0.17).

## Test

Use **Native at 2x**. Clear Vulkan cache once, replay the usual section including
the battle, exit normally, then repeat without clearing. Export the log after
both runs. Pause the emulator if called away. Note visual changes, sustained battle
slowdown or unusually long individual pauses, even if total stuttering improves.

No extra settings or driver download are needed. This shader update naturally
creates new cache entries; an old-version warm cache is not a warm 0.0.13 run.
Custom hybrid/forced TEV paths also use the new generic lighting programs. Compute
coverage has not expanded; repeating all three profiles is unnecessary for Awakening.

## Limits

Runtime selection adds GPU work and may increase the cost of an individual generic
shader. Thor testing must show whether family reduction outweighs that cost and
preserves the warm result. Structural lighting, procedural effects, typed resources
and native pipeline states still require distinct programs/pipelines. First-use
compilation remains possible; this is not a zero-stall claim. Host pixel comparisons
check agreement with the inherited specialized renderer, not complete hardware accuracy.

No Android permissions, package identity, signing policy, external services or driver
workarounds change. Publication occurs only after all existing and expanded gates pass.

## Local validation

7,400 family/source/idempotence checks pass, including 3,648 merged pairs and 52
retained distinctions. Mesa llvmpipe matches **425,984 exact RGBA8 pixels** and
425,984 depth/discard results across all 416 full fragment cases. The existing
57,344 TEV color and 57,344 texture-use comparisons pass. Production host probes,
Vulkan integration syntax, all 163 Android setting keys and eight manifest-policy
checks also pass. All **591 distinct complete Vulkan programs** compile and pass
SPIR-V validation with optimization off and on (1,182 validations), including the
TEV loop hint and all seven push-constant offsets. Full Android compilation and
final APK/signature checks remain required in Actions before publication; CI repeats
the shader gates as well.
