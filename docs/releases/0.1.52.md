# Uberhar 0.1.52

<!-- CodexAstraLocal: Describe concrete runtime changes and keep source validation separate from measured device recovery. -->
This candidate addresses shader selection that could become stuck on menu-era
owners, reduces redundant fragment work, and narrows Android development to Native
and Combo. Recovery of earlier gameplay performance requires device comparison.

- Lighting reservations now permit bounded observation and compatible replacement
  after a scene change. Existing compile budgets, lifetime ownership and lighting
  capacity remain bounded; full shaders can replace stale owners without taking
  a reserved lighting slot for an incompatible draw.
- Static TEV shaders use first-use locals where state is fixed. Turning off
  **Remove unused fragment work** now selects a genuinely unpruned emitter, while
  independent sample/arithmetic controls keep their meanings.
- Compatible graphics draws can retain an existing larger render area when their
  actual scissor remains inside it. Equal-size RGBA8 transfers between distinct
  single-mip images can use exact copies instead of linear blits. Existing memory
  ownership and synchronization remain in force; counters expose actual use.
- CPU Software and Combo (generic fragments) are no longer selectable Android
  modes. Existing saved values migrate to Native and Combo respectively, with
  explicit diagnostics. Native/Combo retain their complete generic cold path.

<!-- CodexAstraLocal: Do not present the withdrawn Software wrapper as a new optimization or impose a CPU occupancy ceiling. -->
No new CPU pixel switch is included. The inherited software engine remains a
reference; replacing presentation alone cannot make its tested low throughput
competitive. High CPU demand is welcome when it increases correct sustained
speed, and earlier three/four-core utilization figures are not ceilings.

<!-- CodexAstraLocal: Diagnostics identify consumers and costs without claiming counted work equals saved GPU milliseconds. -->
Admission histories, actual selected shader identities, contained-area reuse and
copy counters support comparison with earlier builds. Optional timings remain
sampled and bounded. A separately built exact-0.1.48 CPU-only comparison preserves
that version's GPU implementation and is not part of this main release.

The usual shader, Android, approved signing and publication gates apply. Host
checks cover scene-transition admission, incompatible replacement controls,
fragment output, translated copy pixels and saved-mode migration. Dark Moon
hardware testing follows; there is no claimed frame-rate gain before that test.
