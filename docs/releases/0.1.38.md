# Uberhar 0.1.38 — vertex preparation and draw ordering

<!-- CodexAstraLocal: Describe delivered behavior separately from the still-open
multicore objective and private architecture experiments. -->
CPU vertex preparation now reads the requested packed format, element count and
loader component directly, avoiding temporary twelve-entry arrays. Little-endian
storage, valid indices, padding, defaults and the inherited loader output remain
unchanged. Synthetic host and ARM64 controls compare the actual loader against the
old decoders, including live input changes and deliberately broken field reads.
Bounded Thor constructor observations support the work reduction; they do not
establish a complete-game speed gain.

The CPU Vulkan path reserves vertex-buffer space before final render-pass and
pipeline setup. A buffer-wrap wait can submit the previous command buffer; the
old ordering could then issue a draw without reopening its pass or rebinding its
pipeline. Upload and allocation commitment remain at the final draw tick, and the
optional fragment owner is completed once after the draw is queued. Finite
recording controls cover current/older ticks, pass changes, samples, payload bytes
and two defective orderings. This is a narrow CPU-path correction, not a general
stream-resource lifetime repair or a proven cause of Dark Moon's recorded flashes.

<!-- CodexAstraLocal: Keep profiling explicit and separate from normal rendering
and from measured performance; historical APK validation remains supported. -->
The Uberhar Android flavor permits explicit profiling by Android's system shell
tools while remaining an optimized, non-debuggable release. It starts no automatic
capture. Packaging checks the actual merged manifest; existing native symbol
artifacts support analysis of a short profile in the next single opening per mode.
This follows Android's [release-app profiling mechanism](https://android.googlesource.com/platform/system/extras/+/main/simpleperf/doc/android_application_profiling.md).

The completed .35–.37 architecture, cleanliness and device reviews remain the
current full-audit anchor. .37 averaged approximately 32% normal speed in its
bounded Native and Combo observations, with unequal scene populations. Sustained
99%, heavy useful multicore execution, 4x and broader gameplay remain unqualified.
The participant-context/typed-dispatch experiment was not selected because its
complete-path host costs were mixed to slower. Shared wake coordination and
same-draw overlap remain separate research; independent Calculated rendering and
the separate narrow memory-return correction are not included.
