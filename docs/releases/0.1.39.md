# Uberhar 0.1.39 — bounded overlap for substantial CPU draws

<!-- CodexAstraLocal: This alpha introduces a guarded asynchronous CPU route;
source/host controls do not establish Thor throughput or graphical qualification. -->

This candidate lets eligible Native and Combo CPU vertex draws overlap while the
emulation owner prepares later Vulkan work. Each packet owns its inputs, uniforms,
compiled shader and output. Its original within-draw FIFO and shader state remain
serial; different packets can execute on different CPUs. Vulkan draws retain their
original order and complete output.

The first live scope requires the qualified ARM64 shader/guest-status contract,
no concurrent guest-memory writers, no geometry shader or diagnostic observer,
complete List/Shader triangles and coherent Vulkan upload memory. At least four
logical CPUs must be available. Draws need 96–255 submitted vertices, at least 96
actual FIFO misses, a validated minimum of 35 non-move arithmetic instructions per
invocation and at most 70 captured input bytes per miss. Other work uses the
existing path, including parallel processing within larger draws. These thresholds
exclude known losing host cohorts; they do not guarantee a target-device gain.

<!-- CodexAstraLocal: Map each ownership change to its actual ordered consumer. -->

- An immutable JIT lease keeps the exact compiled code and source identity alive
  after live setup/cache changes. Stale or unprepared bindings cannot obtain it.
- A sleeping coordinator and the existing worker pool progress independently of
  the emulation and Vulkan owners. Capacity follows available logical CPUs, with
  one reserved for the emulation owner. The queue is bounded at 64 packets and an
  8 MiB accounted payload/object budget; this is not a total RSS or code-cache cap.
- The owner captures bounded raw input bytes and keeps PICA/Vulkan state and
  resource preparation ordered. Completion publishes original final primitive
  state before topology, ordinary work, interrupts, command-list return and saves.
- Coherent stream reservations are sealed at the final draw tick. The ordered
  Vulkan worker waits for exact 88-byte vertex output, copies it once, then binds
  and draws before submission. Generation checks reject stale reservations.
  Missing framebuffer targets preserve output for the next draw as before.
- Before-publication refusals retain ordinary execution. A published task failure
  is terminal through the existing recovery channel; it is never silently replayed
  or counted as rendered. Ordinary diagnostics distinguish deferred work from
  synchronous timing and expose queue width, useful workers and refusal counts.

A new explicit-serial passive memory helper retains global PSI pressure, selected
vmstat counters and memory occupancy with bounded reads and timestamps. It uses
the existing local ADB connection and changes no device policy. DDR traffic/rate/
utilization and hardware cache/stall counters remain unavailable until a real
validated reader exists. No profiler starts automatically.

The prior CPU/GPU placement audit found GPU vertex processing in a minority of the
recorded cold Fire Emblem Combo batches, while fragment processing remained on the
GPU and Native could also be GPU-limited. This candidate does not change fragment
placement or force supported GPU draws back onto the CPU. Future placement tests
must compare complete-frame cost and preserved output.

<!-- CodexAstraLocal: Maintain the required publication and device evidence boundary. -->

Actual-source JIT, queue, primitive-retention and stream-order controls accompany
this candidate. The existing shader, Android, package, signing and publication
gates remain required before installation. Host/QEMU and controlled Vulkan
recording endpoints do not establish Adreno execution or title speed. The finite
host cost comparison rejects tiny/light and isolated queued work; heavier work
benefits only with useful overlap. Target-device tests are pending at preparation.

There is no claim of sustained 99% normal speed, all-core saturation, complete
Calculated rendering or a 0.2.0 milestone. Circle Pad Pro Calibration has no usable
port from the scoped source search and remains low priority after 1.0.0.
