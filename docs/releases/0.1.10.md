# Uberhar 0.1.10 — bounded ready fragment specialization in Combo

<!-- AstraPro: Prepared candidate; published/CI/device status is reported separately at handoff. -->

## Changes

Combo may use ready inherited GLSL specialized fragment modules with its existing
ready GPU vertex/fixed-GS pipeline. Native and Compute keep the forced generic
CPU-vertex control. CPU first-use/recovery remains complete; no shader arithmetic,
accuracy guard, guest clock, drawing order or driver workaround is relaxed.

Bound optional fragments to 128 modules, 64 exact-key demand slots, 16 matching
observations for admission and one optional fragment compiler in flight. Cache
identity includes full FS config and an immutable profile. Reuse does not depend
on hash equality alone. Pending/failed/capped resources keep the full CPU draw.
Optional modules are memory-only and separate from mandatory shader caches.

Preflight fragment readiness before speculative vertex scans/uploads, recheck
final synchronized state, and skip unused generic TEV transport for specialized
GPU-only attempts. A CPU retry prepares its complete transport afresh. Optional
specialized pipeline driver errors are recoverable independently of the generic
versus specialized diagnostic label. Existing shader/pipeline lifetime drains,
framebuffer cancellation and assembly/winding guards remain required.

Add bounded fragment/optimized-route/preflight/transport diagnostics, 1-in-1024
host GPU-attempt samples (not GPU execution timing), and frame-end mode/resolution
ranges that preserve raw intervals while identifying mixed/unknown settings.
Bound the full-fragment pixel oracle's resident program cache without changing
its cases, shader math or tolerances. New comments/notes use AstraPro; old credit
is retained. No workflows/signing/dependencies/permissions are changed.

coverage automatically means faster emulation.
