## Correct optional GPU admission

CPU triangle submission flips opposite quaternion signs before interpolation.
Android disables the inherited geometry-shader correction for performance, and
this Qualcomm driver does not expose fragment barycentrics. Combo previously
promoted lit draws despite neither correction being available. Uncorrected signs
can change interpolated lighting normals, even though each vertex represents the
same rotation individually.

Both Combo presets now retain the complete CPU draw when lighting is enabled and
neither GPU correction path is enabled. The check runs before speculative index
reads, uploads, fragment warming or pipeline construction. Unlit promotion and
devices with an enabled correction path retain their existing eligibility.
Custom admission rules and the Android geometry-shader workaround remain unchanged;
the shared format correction below also applies to Custom's generated vertex code.

This restores a source-proven parity requirement. It is not yet proof that Dark
Moon's recorded ghost is fixed: no game data or Adreno execution is available here.
Affected scenes can become more CPU-bound. This is a correctness change, not a
claim of higher frame rates. It also prevents creation of the rejected optional
pipelines, but the effect on driver memory requires another device measurement.

## Correct three-component attribute padding

For a three-component format that Vulkan must fetch using a wider four-component
format, the generated vertex shader previously forced the extra `w` component to
zero. PICA's CPU input loader supplies one. The generator now restores `w=1`
before executing the guest shader, preserving real four-component input values.
Production CPU/interpreter and generated-GPU fixtures reproduce this independent
parity defect. The supplied log does not show that Dark Moon used the affected
format, so this is not assigned as the ghost's cause.

The existing source-derived shader cache version includes the edited generator
files. Old compiled vertex code is regenerated through normal cache validation;
no manual cache deletion or unrelated driver workaround change is required.

## Missing memory evidence, within the existing cadence

The existing periodic health and before/after-native-run snapshots gain bounded
`/proc/meminfo` system availability and, where readable, two fixed own-process
Qualcomm KGSL counters. These measure kernel-tracked GPU allocations and the subset
mapped into the CPU address space; they are not pipeline sizes or total GPU
residency. Unknown/denied values stay unknown. No additional worker, permission,
mapping scan, bundle or GPU wait is added. See the
[diagnostic reference](../UBERHAR_DIAGNOSTICS.md) for sources and limits.
