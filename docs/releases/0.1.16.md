# Uberhar 0.1.16 — lean text logs and service-independent crash retention

<!-- AstraEH: Owner requested existing log structures, less background work and GammaOS compatibility. -->

## Changes

- Keep current/previous/older text logs as the only continuous file logging. Remove
  the duplicate private journal and all new per-launch session folders/ZIP bundles.
- Use one small run marker. An unfinished run or recorded error causes the next
  startup to save a dated plain-text copy before rotation. Normal launches accumulate
  no archives. Existing crash-report access exports/deletes saved files individually.
- Remove Android process-exit-history/tombstone collection and the periodic Java
  logging worker. The existing native logger flushes quiet tails using a bounded
  one-second wait, with no file operation when nothing new needs flushing.
- Preserve source and marker if an incident copy fails; suppress rotation and append
  so a later launch can retry. Previously committed reports are never overwritten.
- Migrate useful old session evidence to plain text and reclaim ordinary duplicate
  folders. Already-collected binary traces stay available as separate files; no new
  ones are collected. Unknown old files and failed migrations are not discarded.
- Keep the visible storage warning for actual failures and preserve bounded Java
  exception text before chaining the existing uncaught-exception handler.

No renderer change or new gameplay measurement. Dark Moon's image/crash issues remain
open. Comments continue to use AstraEH. Existing build, shader, package and signing
gates apply. 0.1.15 passed those gates; its owner device test is still pending.

## Portability and cost

The inherited Android frontend still needs ordinary UI, storage, input and graphics
APIs. The current minimum is API 29 (Android 10), with ARM64 release builds. Core
logging now does not depend on Android exit reports or Google/vendor background
services. No new runtime library, permission, network service or telemetry SDK is added.
Existing optional device-health samples tolerate missing values and remain capped at
one sample per 30 seconds. This is a compatibility design, not verified GammaOS support
or a promised performance increase. GPU/driver and physical-device checks are still needed.

Forty ordinary-launch host tests leave one marker below 2 KiB. Failure text is bounded
at 65,536 characters. The original 100 MiB text-writer cap remains. Extra full-log IO
occurs only during incident recovery or requested export, not continuously. Preserved
incidents stay until explicit deletion and can therefore accumulate with repeated
crashes; ordinary sessions cannot. Restart recovery/one-time migration can take storage
IO time before logging starts. Quiet worker shutdown has a bounded one-second wait.

## Evidence and limits

20 JVM retention/export tests pass, covering repeated clean/interrupted launches,
clock rollback, failed provider copies, failed marker replacement, damaged markers,
bounded Java text, explicit deletion and old-evidence migration. Production native
writer/worker tests cover quiet-tail flushing without Java scheduling, barriers and
shutdown, SIGKILL, append, rotation, storage failures and the size cap. Additional
queue and 10,066 rotation-policy checks pass. Android provider/UI and GammaOS device
validation remain pending; host checks do not substitute for them.

An active marker means **interrupted**, not necessarily crashed. Reports retain
pre-crash log bytes and recorded Java/handled errors; a fatal native stack, exact
crash timestamp and final queued records are not guaranteed. Filenames explicitly
use process-start time when the true exit time is unknown. No custom fatal-signal
handler is introduced in this simplification.
