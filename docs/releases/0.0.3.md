# Uberhar 0.0.3

Third Android ARM64 alpha, based on Azahar 2126.1.2. This build addresses a
compiler scheduling problem found while investigating long pauses reported in
Fire Emblem Awakening. It is not a confirmed fix for every pause on the Thor.

Download **uberhar-0.0.3-arm64.apk** below and install it over Uberhar 0.0.2.
There is no need to uninstall Uberhar or Azahar. The application identity,
permissions and pinned signing certificate are retained.

- Compile fallback shaders and pipelines on a dedicated serial worker. Optional
  fallback work no longer occupies the specialized shader/pipeline worker queues.
- In normal hybrid mode, admit only one unfinished fallback pipeline at a time.
  Defer additional warm-up work while continuing to use already-ready fallbacks.
- Queue the whole fallback build off the rendering thread, including driver work.
- Log effective renderer settings, the first 20 pipeline waits above 50 ms,
  fallback build timings, and session totals/maxima. All changes are attributed
  to **AstraEH** in code.

## Awakening retest

1. Select **Vulkan**, enable **Uberhar hybrid TEV (experimental)** and leave
   **Force TEV fallback for comparison** **off**. Restart the game.
2. Keep the same driver, resolution and other graphics settings as the previous
   run. Leave the existing shader cache intact for this first retest. The update
   changes upstream's source fingerprint, so the first launch may regenerate
   cached shader programs before gameplay; compare in-game pauses separately.
3. Play a short, repeatable section. Note roughly how long a pause lasts and
   whether it returns when replaying the same section.
4. Exit the game normally and use **Share Log** before opening another game.
   Include the log and a screenshot of the graphics settings in feedback.

The shader comparison gate still validates the GLSL-based specialized path;
record whether **Enable SPIR-V shader generation** is enabled in device tests.
For a controlled cold/warm comparison, follow the
[testing guide](https://github.com/RegiRex/uberhar/blob/uberhar/hybrid-shaders/UBERHAR.md#first-device-test).
A warm-cache improvement alone does not establish a speedup from this change.

New shader families, vertex shaders and unsupported fragment states can still
pause. Hybrid mode preserves draws, overriding upstream asynchronous draw skipping.
Force mode is for correctness comparisons and can cause much longer waits.
Separate compiler queues cannot prevent driver-internal locks or CPU/GPU resource
contention. No game-specific or device performance fix is claimed without testing.

Publication requires the Android build, shader comparisons and existing package,
manifest, ARM64 dependency, alignment, signature and certificate checks to pass.
Screen synchronization and model-clarity changes remain later phases.
