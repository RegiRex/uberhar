# Uberhar 0.0.5

Android ARM64 experimental alpha for Ayn Thor. Install **uberhar-0.0.5-arm64.apk**
over the existing Uberhar installation. The save/share log picker from 0.0.4 is included.

## Why this update

The owner's 0.0.3 normal-hybrid Awakening cold run recorded 121 scheduler pipeline
waits totaling **18.221986 seconds**, 68 waits of at least 50 ms, and a maximum of
**1.083535 seconds**. Only 78 fallback draws were selected from 721 observations
of pending specialized pipelines. The source committed each queued draw to a
specialization even if its compatible fallback completed while that draw waited.
See [the log analysis](../UBERHAR_LOG_ANALYSIS_2026-09-24.md) for evidence and limits.

## Changes

- **Use the first ready compatible pipeline.** Selection happens on the command
  worker. When both candidates are unfinished, an event wakes the draw when
  either finishes. If both are ready, the specialized pipeline wins. No draws
  are skipped, no polling loop is added, and forced comparison mode remains explicit.
- **Track the actual bound pipeline.** Subsequent draws compare against the
  pipeline selected by the command worker, so a late fallback cannot leave a
  specialized draw using the wrong handle. Every fallback draw receives its own
  captured TEV constants.
- **Move hybrid cache probes off the render thread.** On-demand hybrid pipeline
  creation now runs on compiler workers. Startup cache loading retains its
  existing behavior. This avoids directly entering a potentially contended
  driver call from normal hybrid draw submission.
- **Request fast temporary fallback compilation.** Only TEV fallback pipelines
  use Vulkan's `DISABLE_OPTIMIZATION` creation flag. Specialized pipelines retain
  normal optimization. The flag may reduce creation time at the cost of slower
  fallback GPU execution; actual Qualcomm behavior still needs measurement.
- **Add useful diagnostics.** Log specialization/fallback queue time, separate
  vertex/fragment/geometry dependency waits, driver-call time/maxima, first-ready
  waits, late fallback selections, and the pipeline keys/states at long waits.
  Progress summaries are attempted every five seconds while draws continue;
  final totals are still emitted after workers drain. Detailed slow reports are capped.

The single unfinished fallback admission limit and bounded caches remain. The
TEV math and support exclusions are unchanged. First-use pauses can remain for
new vertex/geometry shaders, unsupported states, new pipeline families, and
shared driver/compiler contention. This is not yet a complete precompiled
ubershader system, and no Thor speedup is claimed before testing.

## Retest

1. Use the same driver and **2x resolution**, with **Hybrid TEV on**, **Force TEV
   fallback off**, and the other settings unchanged from the supplied log.
2. Exit to the library, long-press Awakening, then **Delete Shader Cache → Vulkan → OK**.
3. Play the same section once, then exit the game through the emulator menu.
4. Keep Uberhar open and replay the section without clearing the cache. Exit again.
5. Use **Options → Save or Share Log → Current session → Save to file** and attach it.
   Note whether the cold pauses shortened and whether any graphics changed.

Changing pipeline sources can trigger upstream shader-cache regeneration on the
first launch. That startup work should not be confused with in-game waits.
There are no Android permission, signing identity, or runtime dependency changes.

Validation covers the production completion primitive (including 1,000 publication
races and a local ThreadSanitizer run), Android compilation, log naming, shader
numerical comparisons, Vulkan fragment validation and APK installation/signature
checks. These do not replace actual Vulkan rendering and performance testing on Thor.

The Vulkan flag's defined tradeoff is documented by
[Khronos](https://docs.vulkan.org/refpages/latest/refpages/source/VkPipelineCreateFlagBits.html).
