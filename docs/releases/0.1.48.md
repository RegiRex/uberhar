<!-- CodexAstraLocal: Describe implemented workload coordination without claiming a measured Thor speedup or treating occupied CPU cores as success. -->
Native/Combo reuses draw-local vertex-loader layout and completed shader/geometry
setup when an optional deferred attempt is refused. An immutable shader-policy
check runs before uniform/default copies and guest attribute mapping. Synchronous
execution still fetches current input memory after earlier work is reconciled;
no mutable guest-memory cache persists across draws.

<!-- CodexAstraLocal: Preserve the exact grouping limits and independent forward-progress contract. -->
Small independent complete List/Shader draws may join an already pending,
cost-qualified group with an eligible seed. Capture and submission recheck actual
FIFO misses, shader independence, copy volume and group ownership. An opportunity
that disappears before publication takes the existing synchronous CPU route.
Pure tiny streams do not wait for a group to fill. Worker dispatch groups ready
packets by estimated arithmetic work, and the owner retires only the completed
ordered prefix. Guest-memory, interrupt, topology and command-list boundaries
retain blocking reconciliation. Existing GPU vertex placement remains unchanged.

<!-- CodexAstraLocal: Separate process thread counts from participating auxiliary execution and retain mandatory owner progress. -->
Existing ParallelWork pools share a nonblocking auxiliary-execution budget based
on allowed logical CPUs. Persistent workers sleep when idle; no per-draw thread
creation/destruction is added. Nested helper work remains within its current
permit, and an asynchronous draw coordinator reserves progress capacity before
accepting packets that Vulkan may wait on. Guest execution and submission do not
block waiting for auxiliary permits. Compiler, Android and driver threads are
outside this budget; it is not a limit on all process threads or a CPU-affinity
assignment.

<!-- CodexAstraLocal: Explain conservative adaptation and measurement limits rather than implying perfect hardware-headroom detection. -->
Each participating pool gradually trials its helper count using sparse, comparable
complete CPU-work samples. Stable windows and rollback reject changes that worsen
work time; pacing and GPU waits are excluded from the measured pool scope. This
adapts useful participation rather than targeting a CPU percentage. Variable
workloads or insufficient samples can leave the conservative budget unchanged.

<!-- CodexAstraLocal: The retained Fire Emblem capture establishes dead texture demand, not an ARM64 arithmetic repair or whole-game qualification. -->
CPU Software uses backward texture-combiner liveness to avoid evaluating texture
work whose result is overwritten before final output. The captured Fire Emblem
case preserves final triangle output without consuming its irrelevant invalid
texture coordinates. Live invalid inputs still stop with evidence. Dark Moon's
captured texture input remains live and its failure is not declared fixed.

<!-- CodexAstraLocal: Keep independent Calculated execution and explicit first-failure evidence boundaries. -->
Calculated applies corresponding consumer-liveness rules and retains immutable
original inputs, programs, uniforms, generated shader modules and available
completion status across asynchronous failure boundaries. Failure archives keep
exact packet/submission ownership, distinguish missing data, and are written
outside queue locks. A failed predecessor cancels its dependent packet without
misattributing the original failure. GPU-only image contents can be unavailable;
these archives do not promise complete pixel replay. No Native fallback, skipped
unsupported draw or invalid-value replacement is introduced.

<!-- CodexAstraLocal: Permit deliberate optimized-build profiling without starting an observer or exposing a debuggable build. -->
The Android manifest permits explicit shell profiling of the optimized app.
This starts no recording automatically. Temporary qualification diagnostics carry
`CodexAstraLocal TEST-ONLY LOG` comments and removal conditions.

<!-- CodexAstraLocal: Local controls and publication gates are distinct from actual hardware acceptance. -->
The existing shader, Android, signing and publication gates remain required.
The native integration build and eight focused Software cases pass. Shared-budget
and nested-worker controls, owner-prefix controls, and grouped-queue controls on
the host and ARM64 under QEMU pass. One deliberate-defect fixture expectation was
corrected to its earlier valid failure message; runtime code was unchanged and
only the affected remaining checks were repeated. Independent scheduling source
review found no remaining blocker in the reviewed contracts.
Thor gameplay must establish Native/Combo throughput and pacing and whether
Software/Calculated advance beyond prior failures. Calculated's midpoint-color
discrepancy and the actual Dark Moon failure cause remain unresolved. The release
does not claim sustained 99% speed at 4x or an increase to any fixed CPU-core usage.
