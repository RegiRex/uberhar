# Uberhar 0.1.42 — Android CPU Software experiment and deferred draw queues

release/device evidence before describing this experiment as qualified. -->

This experimental build introduces an explicit Android
**CPU Software** graphics mode at 1x resolution. It reuses the emulator's existing
CPU instruction translation, system services and software PICA renderer. Guest
triangle rasterization, texture/fragment processing and depth operations execute
on the CPU; the Android GPU displays the completed image. This is separate from
Native, Combo and the unfinished Vulkan-compute Calculated method.

The Software experiment includes one, two or automatic rendering participants,
using available host CPUs rather than permanently assigning physical core IDs.
It includes Android presentation using existing input controls, checked
framebuffer capture, mip/minification/magnification filtering, cube and shadow
sampling, and bounded frame ownership. Overlapping texture/framebuffer memory
retains serial raster order. Its speed and whole-scene
correctness have not yet been measured on Thor. It is initially a feasibility
experiment at native resolution, not a claim of 2x/4x or 99% performance.

<!-- CodexAstraLocal: The real repeated-renderer regression exposed an inherited
attachment bug; describe the resulting fix separately from expected speed. -->
New Software renderer instances initialize their cached framebuffer addresses
and remap missing active attachments. This fixes a null attachment exposed when
recreating the renderer with different worker budgets. The native checks pass
100 assertions across capture, filtering, actual textured triangles and alias
handling; the standalone release gate reuses the capture/filtering cases.

<!-- CodexAstraLocal: Preserve semantic ordering while removing only a proven
logical no-op barrier; report scheduling opportunity separately from speed. -->

Native and Combo can retain independent complete-triangle CPU jobs across
redundant topology writes and primitive restarts. Real topology changes, partial
triangles, winding, interrupts, guest scheduling, serialization and memory
visibility retain their existing completion boundaries. Pending tickets preserve
the exact saved primitive tail until ordered reconciliation. The existing pool
lets workers take additional independent packets as they finish; Vulkan and PICA
still consume results in guest order.

The focused queue regression passes ordered vertex-output, saved-state, count
and terminal-error checks. Deliberately restoring the redundant wait or losing
the saved tail is detected. Source review passes. Hardware counters will show
whether real workloads gain overlapping packets; no throughput gain is claimed
before those tests.

Planned device checks are one cold Dark Moon opening per applicable mode: Native
and Combo at Vulkan 2x/normal speed, plus CPU Software at 1x. Keep simulated 3DS GPU
timings enabled, reset File 1 and clear the title's shader cache before each run.
Collect ordinary logs, brief images, CPU/thread utilization, exposed aggregate
GPU counters, memory and power/temperature conditions. DDR bandwidth remains
unavailable unless the device exposes a real counter. Exit normally and return
the displays to the owner's idle configuration. The owner judges noticeable
moon/ghost artifacts.

Calculated production integration continues in isolation. Unfinished work is not
a Native fallback and is not presented as a usable replacement in this build.
The existing shader, Android, signing and publication gates remain required.
The host gate also exercises Software framebuffer capture and texture sampling;
native tests compare actual textured raster output across worker budgets.

## Observed device result

All release gates passed and the compatible APK was installed. Native and Combo
completed one cold opening each at 2x with timings on; mean speeds were 69.061%
and 64.865%. Auxiliary CPU queue work is now observed, but 99% remains unmet.
CPU Software stopped before the title menu on an invalid LCD framebuffer span;
it has no gameplay performance result. A correction is being prepared for .43.
See the [device review](../UBERHAR_TEST_REVIEW_0.1.42.md) for scope and limitations.
