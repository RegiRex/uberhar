# Cleanliness review through 0.1.40

The separate .38–.40 source cleanliness review passes for release
`7bc71c5c9c7e10a39558084392330faa884889ba`, tree
`41253ccf403bf3f97be2109374d543d0bb311609`. The source-audit reviewer traced
purpose and consumers independently of the CPU architecture reviewer. This
document carries that completed review forward; preparing it did not repeat the
audit, compile the project or rerun a game.

The ledger covers 184 code, tool and workflow paths, including 79 production
source files. Seventy-five paths, including 33 production files, were reviewed
after the corrected .37 anchor; 109 earlier entries carry coverage only after
exact byte comparisons. This is not a fresh review of every unchanged dependency.
Changed logical sections have adjacent `CodexAstraLocal` purpose explanations,
and historical attribution is preserved.

<!-- CodexAstraLocal: Identify each resolved finding and preserve validation whose result still has a real consumer. -->
Four findings were resolved. The fragment-bank comment now states eight full
and eight partial owners, including retirement. The historical `AstraPro` marker
remains beside the broadened optional-worker explanation. The temporary input
mapping validator no longer selects a loading recipe it never executes; its
range, format and mapping checks remain, and the actual packet still prepares
its recipe. The existing static-demand replacement counter now has a bounded
reporting consumer, explicitly describing probation turnover rather than module
eviction. None of these changes establishes a measured performance gain.

The .38 packed register getters feed the actual vertex loader without a new
cache or duplicate decoder. CPU geometry reservation feeds the original upload
and final-draw-tick commitment. The flavor-specific shell-profiling declaration
starts no profiler and does not make the release debuggable.

For .39, the immutable JIT lease, copied inputs and uniforms, effect proof,
coherent upload generation and packet credit all protect live consumers.
Completed output feeds the hardware-vertex writer and ordered draw; the final
primitive pair feeds owner reconciliation. Unused packet accessors, unused
FP-status capture and lock-only statistics were removed before publication.
The submitted count remains because diagnostic cadence consumes it. Failure
drainage, memory guards and portable wait alternatives remain purposeful even
when a measured run uses only one coordinator.

<!-- CodexAstraLocal: Distinguish a prepared shader structure from remaining owner work and preserve both fragment tiers' actual lifetime consumers. -->
The .40 prepared TEV structure, fragment family, profile and interface policy
feed exact module and pipeline identity. Generated arithmetic retains consumed
operands, lazy texture fetch and delayed combiner-buffer semantics. Dynamic
lighting, texture and framebuffer state still consume the existing 128-byte
transport and 88-byte CPU vertex interface. The 100-byte plan copy and hash at
eligible lookups remain real owner work; “prepared” does not mean every draw
performs no preparation.

Full and partial fragment tiers retain independent demand, owner, attempt and
retirement accounting. Full-ready selection wins, and full promotion continues
while a partial route renders. Ready hits remain valid after attempt exhaustion.
Native's optional worker does not grant GPU-vertex eligibility. Compile durations,
source sizes, selections and queue statistics have bounded reporting consumers;
they do not measure shader execution time or physical driver memory.

All 27 previous required release steps remain, and .40 adds a required static-TEV
step. All 28 passed in [run 37993185551](https://github.com/RegiRex/uberhar/actions/runs/37993185551),
followed by exact asset, signing, manifest and native-symbol checks. Local native

Those adaptations retain the original compile-policy, generic-restoration,
ComboGeneric and GPU-padding cases while exercising the new optional lane and
immutable GPU eligibility. Separate generator controls retain 805 plan checks,
816 × 256 TEV/fetch comparisons, three sensitive emitted defects, 128 Vulkan

Partial/generic color and depth bytes match exactly in the finite host corpus;
the full-specialized depth comparison retains its inherited tolerance. Actual

A failed deferred admission can repeat owner preparation before ordinary
fallback. That is a concrete reuse opportunity, but refusal counts do not price
it or prove that its checks can move across guest-memory boundaries. The
lifetime-retained JIT cache is not bounded by the smaller proof caches. Geometry
leases do not resolve every cached UBO/LUT last-use concern. Optional object caps
do not bound all driver allocation, and memory pressure or frequency is not DDR
bandwidth.

Actual .40 behavior and the four-case GPU-timing comparison belong to the
separate [architecture review](UBERHAR_ARCHITECTURE_0.1.40.md). This cleanliness
closure establishes inspected purpose, ownership and evidence handling, not
complete graphics correctness, sustained throughput or a beta milestone. After
the consolidated report, the owner explicitly authorized the Developer to
implement and hardware-test potential fixes, beginning with cached uniform/LUT
last-use protection. That later candidate is outside this completed .40 audit
and requires its own validation; no empty or diagnostic-only release is selected.
