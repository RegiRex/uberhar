# Uberhar 0.1.44 architecture and purpose review

<!-- CodexAstraLocal: Keep the architect's independent source and purpose review distinct from implementation, execution evidence and release/device qualification. -->

The focused architecture review found no remaining blocker in the reviewed .44 changes. A local native build and the completed controls below passed. Integrated release gates and device output, usability and performance qualification are still pending. These changes do not establish a speedup or guarantee a particular CPU occupancy.

## Architecture

- **Native full fragment preparation:** Native can prepare and select a ready full fragment shader for the existing CPU vertex interface in [PipelineCache](../src/video_core/renderer_vulkan/vk_pipeline_cache.cpp). It uses the existing compiler lane, exact execution-state and shader-owner checks, and separate bounded full/partial banks. The complete generic draw remains available while optional work is pending or refused. GPU guest-vertex eligibility is unchanged; this is CPU preparation intended to reduce repeated GPU fragment decisions.
- **Combo CPU placement control:** The new default-off setting keeps guest vertex execution on CPU in either Combo mode. PICA freezes it at construction and checks it at both optional GPU promotion and ordinary vertex acceleration. Fragment and compute capabilities remain separate. Changing the saved setting requires a game restart; eligible CPU batches may use workers, while dependent work retains its existing execution order.
- **C14 ordered-prefix overlap:** For an admitted synchronous CPU vertex batch with actual workers, the owner may assemble a contiguous completed prefix while later grains finish, using [NativeParallelBatch](../src/video_core/pica/uberhar_vertex_parallel_batch.h) and the existing pool. Readiness is published only after a whole grain completes. The existing full join remains before suffix submission, FIFO reuse, return and GPU drawing. This overlaps CPU append/assembly with CPU shading; it does not enqueue early GPU draws or defer work across guest command boundaries.
- **Reversible append ownership:** The prefix path reserves bounded hardware-vertex storage and snapshots the complete assembler state, including saved slots and winding. A later shader failure drains workers before restoring both. Shader failure takes precedence over speculative append failure and FP flags. Unknown sinks refuse this capability; Software keeps its guest-memory feedback ordering. Small batches, preparation refusal and failed worker startup retain the joined path without readiness publication or an assembler snapshot.
- **Software sampling:** One immutable [demand mask](../src/video_core/renderer_software/sw_texture_demand.h) follows actual TEV operand arity and lighting consumers. The same mask controls texture mapping, alias admission, covered coordinates and helper derivatives. Fixed LOD avoids unused derivatives while preserving min/mag and available-level selection. Finite all-border shadow footprints are classified before integer conversion; mixed edge taps remain intact. Consumed invalid dynamic coordinates still fail explicitly. The inherited stage-zero Software alpha behavior remains unchanged and is a separate parity question.
- **Terminal error delivery:** A typed renderer error inside [Dynarmic's SVC callback](../src/core/arm/dynarmic/arm_dynarmic.cpp) is retained, halts the JIT actually executing, and is rethrown only after generated code returns to C++. Run/Step check the terminal latch before further guest execution, including debugger early returns. This contains the error without replaying a partially completed guest operation or catching unrelated failures.
- **Vulkan allocation:** A [descriptor pool](../src/video_core/renderer_vulkan/vk_resource_pool.cpp) now has capacity for at least the actual 64-set batch; set and per-type array budgets share checked arithmetic. Allocation tries each retained pool once and at most one fresh pool, retrying only exhaustion or fragmentation. Failure rolls back unpublished growth and preserves live owners/ticks. The review also found post-submission command-buffer acquisition outside the Vulkan worker's failure boundary; it now uses the existing terminal capture and cancellation path. Normal teardown still drains submitted work before destroying resources.

## Purpose and consumer review

This is a separate source assessment by the architect, not a repeat of the developers' execution checks. The changed runtime sections and setting/probe adapters were inspected for adjacent purpose comments, ownership and actual consumers.

The new settings have native, Android and desktop persistence paths. The immutable placement value is used by both affected route decisions and identified once at startup. Native full-fragment eligibility has its own configured-policy label rather than borrowing GPU eligibility. Calculated's labels now describe original-input compute and terminal unsupported draws; they do not claim successful coverage.

The demand mask is consumed by preparation and sampling. The JIT pointer/latch and allocator rollback state have explicit readers and lifetime boundaries. C14 reuses existing input planning, certificates, JIT bindings, workers and FIFO references. It adds no per-vertex clocks or duplicate shader execution. Ordinary pool callers compile out the optional hook.

Temporary prefix counters and first-fault diagnostics carry `CodexAstraLocal TEST-ONLY LOG` purpose and removal conditions. Prefix counts describe completed owner append work; sampled `prefix_ns` includes the hook/check phase and is not a saved-frame-time estimate. Software fault context is constructed only on failure and logged once by the owner after worker drainage. No new unused production result or duplicate hot-path preparation was identified in this reviewed scope. Historical attribution is retained.
